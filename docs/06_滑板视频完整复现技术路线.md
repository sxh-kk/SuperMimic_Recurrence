# 网络滑板视频完整复现：人板交互技术路线

日期：2026-10-23。用户明确要求复现网络单人滑板视频，并选择“直接复现原视频，包括推地、转弯或跳板动作”。目标按 **G1 与被动滑板共同参与物理仿真，最终连续完成视频动作**处理。当前还没有具体视频链接 / 文件，跳板是否指上板、Ollie、Shove-it 或 Kickflip 尚不能确定。

本文为调研与设计，尚未运行滑板控制器、训练滑板任务或验证跳板成功率。当前 LAFAN1 首跑仍按用户要求累计约一小时保存停止，见 [训练记录](04_LAFAN1训练记录.md)。

## 技术判断与推荐

滑板任务需要同时恢复**人、动态板、相机和地面**，再学习足—板—地的交互。当前普通视频流程“人体重建 → G1 重定向 → 平地策略”可作为人体初始化，但还缺板轨迹、接触阶段和轮系动力学。

沿用本项目原本的 SuperMimic 目标，推荐 **HUSKY 的滑板物理场景作为参考，独立验证其控制器后，迁移场景并扩展本项目的人板联合世界模型与模仿策略**。HUSKY 原始策略用于可用基准与对照；其结果与 SuperMimic 扩展分别命名，保留原平地复现。这样可区分视觉恢复、滑板物理与模型式控制各自的问题。

完整视频仍是最终目标。开发时拆分推进、滑行、转弯、起跳、落地训练和诊断，最终须在同一个连续物理回合里衔接，不能把分段成功的回放拼接视为完整成功。

## HUSKY 与本机的兼容点

- 同为 mjlab / MuJoCo，现有板模型更接近本项目软件栈，无需因滑板目标切换到 Isaac Lab。
- [滑板 XML](https://github.com/TeleHuman/humanoid_skateboarding/blob/main/src/mjlab_husky/asset_zoo/robots/skateboard/xmls/skateboard.xml)有自由根、四轮被动转轴、前后 truck、板面倾斜和倾斜—转向 equality 耦合，是真正的动态实体。
- [机器人配置](https://github.com/TeleHuman/humanoid_skateboarding/blob/main/src/mjlab_husky/tasks/skater/config/g1/env_cfgs.py)使用 **23 DoF G1**，当前 SuperMimic 是 **29 DoF**。先用其原始模型和预训练网络验证公开行为，再审查迁移到本机 29 DoF 的关节、惯量、动作和观测映射；不能直接互换权重。
- [观测配置](https://github.com/TeleHuman/humanoid_skateboarding/blob/main/src/mjlab_husky/tasks/skater/skater_env_cfg.py)中 actor 主要读命令、航向、IMU、本体状态、上一动作与 phase；critic 额外读板相对状态、足板 / 足地接触等。不能把“完整板状态必须给 actor”当作 HUSKY 的原设计。我们后续自定义任务可先在仿真中给更多板观测降低调试难度，再单独研究观测删减。
- [README](https://github.com/TeleHuman/humanoid_skateboarding)实测环境是 Ubuntu 22.04 / CUDA 13，固定 mjlab 版本也与当前不同。应在独立环境验证 CUDA 12 和本机驱动，保留当前已经验证的训练环境。
- README 与 [LICENSE](https://github.com/TeleHuman/humanoid_skateboarding/blob/main/LICENSE-CC-BY-NC-4.0.md)标 CC BY-NC 4.0，而 pyproject 许可元数据存在 Apache 2.0 不一致。按明确的非商业限制保留来源，不把上游整套代码改标成本项目 MIT。先放已忽略的 `references/` 独立验证。

## 视频需要恢复哪些信息

```text
原视频与时间戳
  ├─ 背景 / 地面 → 相机运动、世界坐标、坡面或台阶
  ├─ 人物 → SMPL-X 姿态与根运动初始化
  └─ 滑板 → 板形 / 尺度、板端与轮轴关键点、板世界位姿
              ↓ 同步优化人物、板与相机
       左右脚接触标签：踩板 / 蹬地 / 腾空
       阶段：推地 → 收脚上板 → 滑行 → 转弯 → 起跳 / 翻板 → 落板
              ↓ 接触感知 G1 重定向 + 物理可行性校正
       G1 与板的联合参考及置信度
              ↓ 被动板环境中的交互控制训练
       同一回合完整视频动作评测
```

### 人体与滑板必须共享坐标和时间

人体可先用 GVHMR 初始化，但不能把其普通地面接触推断直接当滑板接触真值。脚踩在滚动板上时，脚相对地面应移动，**约束的是脚相对板面的速度与高度**；推地脚才可能相对地面近似静止。板在空中也可离开双脚，不能用“板移动就一定与人接触”的规则处理翻板。

第一版建议使用参数化滑板 CAD 和板头 / 板尾 / 轮轴关键点拟合板位姿，结合背景相机、地面、可见接触帧共同优化。必要时人工确认遮挡前后的少量关键帧。相比直接重建高精度外观网格，先把世界轨迹、板朝向和接触时间做可信，更符合控制所需。

跟拍时人物在画面中几乎不移动，并不代表真实速度为零；必须分离相机运动。滑板常有头尾对称和遮挡，需利用连续性、板图案或可见关键点处理 180° 朝向歧义。严重遮挡或切镜头导致的信息缺失要标低置信度，不能把模型补全当成观测。

WildHOI 的[数据与示例](https://huochf.github.io/WildHOI/)明确有滑板类别，可作初始化 / 标注参考。RHINO 的[论文](https://arxiv.org/html/2605.17014)明确讨论运动模糊、长遮挡及刚体假设；其逐序列完整优化报告约 18 小时 / RTX 4090，这是作者流程的量级，不是本机耗时保证。因此不默认把整套高成本神经场重建作为第一步。

### 跳板片段保留高帧率

保留原始 60 / 120 fps 等高帧率文件及时间戳，板追踪和接触标注优先用原生帧率。GVHMR 如需 30 fps，单独按时间戳重采样人体分支，再与板轨迹对齐，不能把所有原始证据直接丢到 30 fps。物理参考可先统一为本机 50 Hz；快速起跳、翻板和落地是否需要更高控制频率，应做分辨率 / 步长收敛试验，改变控制周期需要重新训练。

单目视频不能唯一确定米制尺度、遮挡中的三维旋转、板质量惯量、摩擦和真实接触力。能提供人物身高、板尺寸或同一动作的其他视角更好；缺少时使用标明来源的模型假设与校准范围。

## 跳板不是普通滑行的自然附赠功能

| 视频动作 | 核心接触 / 动力学问题 | 技术处理 |
| --- | --- | --- |
| 推地 | 一脚支撑板面、一脚与地面产生推进，随后收脚上板 | 接触 phase、推进速度、足板防滑和上板过渡 |
| 滑行 / 转弯 | 无动力轮系、板倾斜驱动 truck 转向、侧向滑移 | 板—轮—地参数及耦合校准，速度 / 航向与视频参考跟踪 |
| 跳上板 / 下板 | 落脚时间、相对速度、冲击吸收 | 双实体同步初始化、接触切换和阶段终止 |
| Ollie | 踩尾弹板、脚与板的离合、空中相对位姿、落板冲击 | 足部与板尾几何、地面碰撞、专门起跳 / 落地课程与数据 |
| Shove-it / Kickflip | 板离脚后大角度旋转、再次接板，可能有不可见翻面 | 高帧率板姿态恢复、分阶段接触约束、专门旋转 / 落地策略；当前开源基线未保证覆盖 |

G1 的脚踝、刚性足底和人体鞋脚的结构不同。目标应验证动作阶段、板轨迹、身体相对板关系与技巧完成，而不是要求所有人体关节角逐字相同。具体视频若涉及手抓板、栏杆、斜坡或跳台，还要增加相应接触和地形，不能按平地自动处理。

HUSKY 的现有板形和接触是推地 / 转向起点。对视频中的板尾弹地、翻板或高速碰撞，需审查板头尾碰撞形状、足底接触几何、摩擦、恢复和仿真步长；可视模型形似不等于技巧动力学正确。最终评测中板保持被动，由机器人关节和真实接触驱动；若使用辅助推力或轨迹牵引训练，须标注并在最终无辅助评测时移除。

## 当前 SuperMimic 实现要修改的范围

本地 `scene` 只有 G1 与 plane。`StateIO` 断言 qpos=36、qvel=35，世界模型、replay 与解析头按 **71 维机器人状态**实现。策略本体历史 930 维、参考目标 680 维，没有板运动参考。直接往场景加入自由板会触发状态维度断言，绕开断言也不能让原模型预测未知的板动力学。

| 部分 | 必需修改 |
| --- | --- |
| 场景 / 物理 | 增加板、轮、转向关节与耦合；区分脚—板、脚—地、轮—地碰撞与摩擦；校准质量惯量 / 阻尼 / 滚阻 |
| 参考库 | 同时保存机器人参考、板位姿 / 速度、阶段 / 接触标签和置信度；轮速可依据滚动假设初始化，但不能称为视频直接测量 |
| StateIO / StateSpec | 机器人与板状态统一编码、坐标归一化、积分和误差；板内部关节状态也需处理 |
| replay / 世界模型 | 重新采集交互数据，训练耦合下一状态；扩展窗口、初始历史、标准化、版本和检查点契约 |
| policy / critic / goal | 增加板相对关系、阶段及未来板目标；现有权重只能评估部分迁移，输入输出不可直接视作完整兼容 |
| 奖励 / 解析头 | 人体姿态、板轨迹、足板相对滑移、接触阶段、推进 / 转向、起跳 / 落地；真实力奖励需要额外预测或明确的几何近似 |
| 重置 / 终止 | 同步重置人、板、轮速和接触阶段；区分允许的推地 / 腾空与跌落、错过落板、异常碰撞 |

只增加自由刚体板的位姿和速度，最低名义状态就从 71 增至 84；若沿用 HUSKY XML 的 7 个内部铰接关节，再计各自角度 / 速度，29 DoF G1 组合的名义 qpos+qvel 为 98，实际仍以合并模型核验。不是简单给目标 CSV 加几列。

该广义状态包含 equality 耦合约束下的冗余关节量，并非 98 个独立自由度；世界模型若全量预测，应检查倾斜—转向约束残差，并设计保持 / 投影约束的积分方式。

板质量 / 摩擦等可作为 episode 内固定上下文；实时接触和板运动是动态量，不能塞进现有恒定 `xi` 代替状态。原机器人 FK 可以保留，新增板几何和接触处理。纯 FK 不提供真实接触力，首版可用几何距离与相对速度作可微代理，并通过真实仿真接触数据验证偏差。

跳跃时接触改变很快，世界模型可能产生“想象中成功、真实仿真失败”的轨迹。因此世界模型须分别评估推进、转弯、离板与落板阶段的多步板 / 脚误差，策略最终成绩始终以真实仿真回合为准。

## 推荐的实施路线与验收

1. **视频审查与事件清单**：收到原链接 / 文件、起止时间后，把推地、收脚、转弯、起跳、板旋转、落地逐段列出，并标记遮挡和跟拍。确定具体跳板类别后再估计任务量。
2. **独立跑通 HUSKY 原始预训练基准**：先验证公开 23 DoF 模型的推地与转向，检查本机 CUDA 12 兼容、无外部推进时的板动力学及可重复评测。此阶段结果标 HUSKY，不标 SuperMimic。
3. **恢复并验收指定视频的人板联合参考**：先完成相机 / 地面 / 人 / 板时间对齐，接触标注，再做 G1 接触感知重定向。输出三维回放，确认板不翻向、踩板脚不被错误固定在世界地面。
4. **扩展 SuperMimic 并分技能交互模仿训练**：以 HUSKY 物理建模和阶段机制为起点，将场景迁移到目标 G1，重新采集联合状态转移来训练世界模型。先建立视频的推地 / 滑行 / 转弯参考跟踪，再训练该视频实际出现的上板、起跳和落地。视频目标、接触条件和策略网络需要新增，原命令控制器不能自动逐帧照做；未做型号映射的 23 DoF 状态不能直接充当本机 29 DoF 世界模型数据。
5. **连续整段评测**：技能衔接保留同一板和机器人状态，不在阶段间隐藏重置。恢复原速，报告整段完成率与所有失败；如训练期间使用降速、辅助支撑或简化板，分别记录并最终在目标条件复测。
6. **算法和工程结果分别报告**：单独命名为 SuperMimic 人板交互扩展，与 HUSKY/PPO 基准、原平地论文复现分别记录。如果后续优先追求尽快实现视频行为，可另行评估 HUSKY/PPO 的视频模仿方案；它属于控制算法替代，当前没有切换正在训练的算法。

当前一小时 LAFAN1 检查点保留为平地跟踪基线及可能的部分初始化，不将它视为已经具备滑板技能。整个目标需要新数据、场景和交互训练，不能承诺只靠该检查点微调几步完成跳板。

HUSKY 公开推地动作不足以覆盖空中翻板。需为目标技巧准备视频参考、人工确认的关键接触帧，并通过可行参考构造、阶段课程或额外示范形成起跳 / 落地训练数据；一段视频不是完整的机器人动力学训练集。

## 4090 上的安排

- 保留本机已验证的 CUDA 12 训练环境；HUSKY 和视频前端单独部署，不按其 CUDA 13 README 直接升级系统驱动。
- 先少量环境验证碰撞 / 接触和约束稳定，再按 256 / 512 / 1024 等规模实测吞吐与显存，决定能否扩大并行；已有 4096 个平地环境的显存数据不能代表滑板模型。
- 视频推理、几何优化和 GPU 物理训练分阶段运行。RHINO 等完整恢复可很耗时，优先短片与参数化板；不把论文中其他机器的耗时直接当本机承诺。
- 跳板阶段需测试物理步长、接触容量与控制频率；调整后重新训练。环境数量、想象批量与 H 应根据真实耦合模型实测选择，当前没有滑板训练耗时或显存结果。

## 最终结果如何判断

并排展示原视频、人板重建、G1 与板参考、真实物理执行。量化至少包括：

- 整段和各阶段成功率、失败时间；阶段衔接无重置的完成情况。
- 板的世界轨迹 / 朝向误差、速度与转弯半径；人体相对板的姿态误差。
- 踩板期间脚相对板的滑移、接触错相、穿透或异常触地。
- 视频包含跳板时的起跳 / 接板 / 落地时刻、板的空中姿态、落地后可继续滑行的比例。
- 原速与任何降速版本分别报告，运动学回放、辅助训练和无辅助物理执行分别标识。

下一步最关键的输入是**具体视频链接 / 文件与起止时间**。据此才能确定镜头与板姿态是否可恢复、需要哪些人工关键帧，以及原视频的技巧是否超出已公开控制器范围。
