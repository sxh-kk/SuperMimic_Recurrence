# Ollie 实际状态全身QP准备段试验

## 实际结果

新增独立CPU入口 `scripts/local/track_ollie_whole_body_qp.py`，以实际状态求全身动力学分配，再转换成原29个位置驱动器目标。**0.10 s短冒烟通过既有质量门槛；同参数0.50 s真实运行因足平面偏差63.16 mm超过40 mm门槛而失败。** 因此停止延长，没有运行完整2.76 s准备段，没有生成已验证教师、训练数据示范或Ollie成功结果。

这不是SuperMimic策略，也不是主训练入口的替代实现。它检验“实际状态下的动力学/接触一致性分配是否比离线静力加踝反馈更容易执行”，当前结果尚不足以证明完整准备控制收益。

参考采用 `data/ollie/tail_contact_upright_v4/joint_reference_50hz.npz`，SHA-256 `38243f1cc2c37ce1461817e83ced08410d90a332692a8c1d44dbb89dd54994e7`。本次只使用其准备部分，不处理后续滑蹭、踩尾、空中与接板；源视频的接触阶段不能由本控制器试验重新定义。

## 求解和真实执行的边界

每20 ms从真实MuJoCo状态构造

`M qdd + h = B tau + J_contact^T f`，其中`h=qfrc_bias-qfrc_passive`。

45维广义加速度通过正定质量矩阵消元，优化变量为29维tau与12×3维接触力，共65维；这与保留qdd的完整动力学等式等价。每次解仍核对完整45维动力学残差，不能靠删除浮根方程作弊。

12个点为左右各4个近似足底点和4轮。足点分别投影到真实center/tail/nose top rectangle，力以所选geom坐标表示；轮地力为world坐标。各点法向非负，摩擦取0.9的保守四棱锥；点力上限沿用工程约束量级：切向±Mg、法向0～2Mg。它们是QP接触假设，不是额外物理驱动。足点投影距离>10 mm或轮底高于地面5 mm时，对应力变量关闭。

tau上下界取两项的交集：原actuator力矩范围，以及当前实际q/qd下原真实关节目标范围可实现的瞬时tau区间。求解后只发送

`qtarget = qactual + (tau + Kd*qdactual)/Kp`。

使用真实actuator名字/索引映射和原Kp/Kd，每个目标保持8个0.0025 s子步。没有板actuator、磁吸、焊接、根/板位姿回写、每步覆盖qpos或施加QP接触力。求出的qdd也不直接写入仿真。质量、惯量、重力、摩擦、碰撞及力矩上限均未修改。

QP软任务为关节参考加速度、相对板的COM、根朝向及足位姿跟踪。实际执行中还需要接触加速度一致性：支撑足在QP模型中保持初始相对板的站姿，轮地法向加速度为硬约束，轮滚动无滑为软任务。**这些只约束预测加速度，物理仿真没有固定足或板**；真实滑移和穿透照常产生并接受原门槛筛选。本入口仅用于双足站板准备，不能拿这一站姿模型直接控制后续视频中的前脚滑蹭或离尾。

另采用保守的控制器加速度信赖范围：腿200、腰80、上肢/腕30 rad/s²。它们限制QP的反作用抡臂方案，**不是改写仿真或声称新增硬件加速度极限**。原目标和力矩约束仍同时保留。

## 数值可行性与未执行的失败解

只依赖现有SciPy：先`linprog`求满足硬线性约束的可行初值，再以SLSQP优化二次目标。tau按原上限、f按Mg缩放；任务按物理加速度尺度归一化。硬约束QR去冗余后，仍核对全部原始行。目标函数整体缩放不改变最优解，未通过收敛/可行性检查的结果不执行。

早期两次0.10 s数值冒烟在t=0分别因SLSQP line search与迭代上限被拒绝，**实际动作数为0**。没有把有限但不可行/未收敛的向量当作成功解，也没有回退到隐藏控制器。对应日志 `logs/ollie_whole_body_qp_smoke_01/02` 保留。

后续数值缩放使求解器收敛，但仅设软足任务的实际0.10 s试验，足偏移91.81 mm、穿透13.40 mm，失败。补充接触加速度一致性后，足偏移降到5.84 mm，但真实穿透17.65 mm，仍失败。独立重放定位到 **0.0525 s right_thigh–right_hand自碰**：QP通过快速上肢反作用纠正COM，首个肩目标比当前姿态增加约1.40～1.49 rad，肘在0.10 s运动约0.91 rad。没有因此放宽碰撞或穿透阈值。

仅针对这一实际机制加入上述关节加速度信赖约束，随后0.10 s通过质量检查。没有进行CEM、大规模参数搜索或反复增加相同训练预算。

## 独立执行核验与解释限制

从保存的唯一初态重新创建原生模型，只用25个已保存实际目标重放全部200子步，控制边界qpos/qvel最大误差 **0**。全部保存state/action/qpos/qvel有限，原控制数组为25×29、状态26×92。没有把QP假设状态存成实际轨迹。

最终25个解的最大残差：

- 完整动力学平衡：**8.7e-13**。
- 全部原始接触加速度约束：**1.8e-11**。
- 原生MuJoCo在相同实际q/qd下计算的actuator force与期望tau：**1.6e-14 N·m**。这是独立模型映射检查，不仅是代数公式自检。
- 控制器加速度信赖范围越界：**2.4e-13 rad/s²**。

这些残差证明实现的瞬时QP方程和驱动映射一致，**不证明QP假定接触力就是软接触仿真的真实力**。在每20 ms保持位置目标期间，实际tau会随q/qd变化；独立重放中其相对每步期望tau的RMS差约 **1.172 N·m**、峰差10.365 N·m。实际20 ms根加速度与QP瞬时预测的XYZ RMS差约 **[1.276,0.958,2.088] m/s²**。软接触分布与20 ms保持均存在模型差异，本次没有单独隔离二者贡献，不把全部偏差强行归因于一个因素。

因此当前不能推荐这份控制器作为准备教师，也没有证据通过只换更快QP求解器就能消除实际滑移。后续若继续，应先定位实际接触/执行闭环误差，保持原生物理质量门槛；不能仅因为求解器收敛或upright高就延长并认证准备段。

## 冻结基线后的任务优先级诊断

进一步只读计算保存的QP预测与实际关节状态，发现**当前QP明显牺牲关节posture，不应主要把失败归给20 ms保持或软接触**。基线关节加速度任务除以腿/腰30、臂80、腕500 rad/s²，而COM任务乘3，关节姿态保持相对过弱。此处量化的是已执行基线，没有立即改权重再挑选有利结果。

首个控制时刻，本应接近保持姿态的29维关节任务期望加速度RMS仅 **2.817 rad/s²**，QP却预测 **30.867 rad/s²**。代表关节：waist yaw期望−0.059、预测 **−61.159**；right shoulder pitch期望−1.264、预测 **+30.000**；right elbow期望−2.322、预测 **+30.000 rad/s²**。后两者命中保守信赖边界，仍朝与关节PD目标相反的方向运动。25个控制步的关节加速度任务残差RMS **49.214 rad/s²**，waist yaw单维138.728。

实际0.50 s关节位置相对参考的整体RMSE **0.341 rad**、最大误差 **1.909 rad**（right shoulder pitch）；waist yaw末误差 **−1.708 rad**，right elbow **+1.246 rad**。可见upright高也掩盖了明显的全身姿态漂移。

同首态COM任务期望相对板加速度约 **[−1.256,−1.348,+0.380] m/s²**，QP预测约 **[−1.020,−1.430,+3.805] m/s²**；root角加速度任务的全25步残差RMS约 **8.780 rad/s²**。因此当前也不是所有高权重任务都被精确完成；SLSQP返回收敛和硬方程残差通过，不代表所有软任务或真实轨迹符合要求。

对比同参考的 `tail_upright_prep_01/contact_feedforward.npz`，QP期望tau与参考静力FF的整体差RMS **14.243 N·m**、峰差70.757 N·m。首态waist yaw为 **−28.932 N·m**，对应静力FF约−0.129 N·m；左右hip roll为 **+46.613/−46.505 N·m**，静力FF约−0.797/+6.153 N·m。QP力分配也明显不同：首态预测轮地法向总和约469.47 N，而静力FF为348.46 N。这里是与参考静力解的比较，后续实际状态已经偏离参考，不能把全部差异当作同状态的求解错误。

这些证据支持下一次只检验**提高posture任务优先级**，保持原力矩/PD目标可达约束、加速度信赖范围和真实质量门槛；不支持增加电机能力、扩大碰撞容差或直接把全部关节加速度硬设为参考值。后者可能与双足支撑的运动学约束不兼容。基线源码与本批失败日志在这一诊断后保持冻结，后续不同任务权重必须独立记录。

```bash
env -u PYTHONPATH -u PYTHONHOME CUDA_VISIBLE_DEVICES='' \
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 uv run --locked python \
scripts/local/track_ollie_whole_body_qp.py \
  --reference data/ollie/tail_contact_upright_v4/joint_reference_50hz.npz \
  --seconds .50 --out-dir logs/new_ollie_whole_body_qp
```

实际动作/状态在 `actual_rollout.npz`；全部求解器诊断、期望tau/假设点力/预测qdd在 `solves.json`；逐子步真实接触和误差在 `contacts.json`。QP力始终只是诊断量。默认仅0.50 s，完整2.76 s没有在本批运行。
