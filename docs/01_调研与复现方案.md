## 1. 找到了哪些开源代码

截至本次检索，[官方项目网站](https://supermimic.github.io/)提供了论文、视频和演示，但未发现训练代码入口。当前可用的是两份非官方复现，不能将它们直接视为作者原版。

论文为 [SuperMimic: Scaling Humanoid Whole-Body Control with One Differentiable World Model](https://arxiv.org/abs/2610.28480)。核心流程是：仿真收集数据 → 拟合可微世界模型 → 通过模型内想象轨迹反向传播来更新策略和 critic；世界模型与策略在训练中交替更新。

| 实现 | 技术路线 | 公开结果 | 建议用途 |
| --- | --- | --- | --- |
| [CuboiLeo/SuperMimic-Reproduced](https://github.com/CuboiLeo/SuperMimic-Reproduced) | mjlab / MuJoCo Warp；包含数据转换、数值测试、训练、整段评测和中文实验记录 | 作者报告：5090 上，加入锚点相对观测后，LAFAN1 1.66 h 达到 0.824，失败 5/40；3.3 h 为 0.904、失败 3/40 | **主线**。依赖较直接，也更方便核查偏离项 |
| [zita-ch/supermimic_vibed](https://github.com/zita-ch/supermimic_vibed) | Isaac Lab 3 kit-less / Newton / MuJoCo-Warp；采用 Docker 工作流 | 作者报告：RTX PRO 6000 上，1.47 h 达到 0.829、失败 0/40 | **备用和交叉验证**。有较完整的演示结果，但额外依赖与实现差异更多 |

以上性能均为仓库作者自报，尚未在本机复核。两份仓库的代码许可证均为 MIT；数据许可证需独立查看数据源。

### 不能忽略的复现差异

1. **mjlab 版本的 0.82 使用了额外观测。** 开启 `anchor_obs` 后，目标输入增加机器人相对参考动作的位置、朝向信息，不能把该成绩当作严格论文同口径结果。
2. **默认观测的实际日志比 README 更新。** 主仓库首页仍将 e7 写为进行中，但实验日志已记录：单卡 e7 在约 1.8 h 时，整段评测回报为 **0.582，失败 3/40**。因此，复现难点包含观测与评测协议，不能只归结于算力。
3. **另一份实现也增加了观测。** `supermimic_vibed` 的策略输入额外加入 6D 参考相对朝向；另有 bf16、关闭自碰撞和额外世界模型预热等选择。

主仓库将默认观测结果的差距归因于长动作的全局漂移和评测协议歧义。这是第三方实现的诊断，尚不能据此判断论文有误。未来参考帧具体包含哪些特征，也需要继续核对。

依据：[主仓库实验日志](https://github.com/CuboiLeo/SuperMimic-Reproduced/blob/d9be385b3eeb13a638fb33fb200d3bfd9be9839f/docs/EXPERIMENTS.md)、[备用仓库观测源码](https://github.com/zita-ch/supermimic_vibed/blob/a1508d42c9d1699a52e8233ab16d08c488441ab9/supermimic/mdp.py)。

## 3. 环境方案：保留驱动，改用 CUDA 12 包

主仓库默认依赖包含 `torch 2.14.1+cu130` 和默认 Warp wheel。CUDA 13 要求 R580 或更新驱动，本机 R570 不适合直接照抄 `uv sync`。容器同样使用宿主 GPU 驱动，单靠 Docker 不能解决这一问题。[NVIDIA 兼容说明](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html)

推荐先尝试以下组合：

| 组件 | 拟用版本 | 核对情况 |
| --- | --- | --- |
| Python | 独立 3.12 | 满足仓库要求；不覆盖系统 Python |
| PyTorch | **2.14.1+cu126** | 已在官方索引确认 Linux x86_64 / CPython 3.12 包存在 |
| Warp | **1.18.0+cu12** | 已在官方 Release 确认 Linux x86_64 兼容包存在 |
| MuJoCo | 3.16.0 | 保留上游版本 |
| MuJoCo-Warp | 3.16.0 | 保留上游版本 |
| mjlab | 上述固定提交 | 避免接口漂移 |

依据：[PyTorch cu126 官方索引](https://download.pytorch.org/whl/cu126/torch/)、[Warp v1.18.0 Release](https://github.com/NVIDIA/warp/releases/tag/v1.18.0)、[Warp CUDA 12 安装说明](https://github.com/NVIDIA/warp/blob/v1.18.0/docs/user_guide/installation.rst)。

这是满足标称版本要求的候选组合，**包已确认存在，但本机 JIT、CUDA 图捕获和完整训练兼容性尚未验证**。首个里程碑就是验证它，而不是直接开始数小时训练。

### 3.2 GPU 验证

先检查两个框架都能使用 GPU：

```bash
env -u PYTHONPATH uv run python - <<'PY'

assert torch.cuda.is_available(), "PyTorch 未检测到 CUDA"
```

## 4. 数据：先用 LAFAN1，保持问题规模可控

首阶段采用 [LAFAN1 G1 重定向数据](https://huggingface.co/datasets/lvhaidong/LAFAN1_Retargeting_Dataset) 的 `g1/`：40 段，约 2.45 h。使用已有 G1 数据，省去从人体动作重新重定向的工作。

在主仓库目录执行：

```bash
env -u PYTHONPATH uv run hf download \
  lvhaidong/LAFAN1_Retargeting_Dataset --repo-type dataset \
  --include 'g1/*.csv' --local-dir data/raw/lafan1

env -u PYTHONPATH uv run python scripts/data/csv_to_npz_batch.py \
  --input-dir data/raw/lafan1/g1 \
  --output-dir data/npz/lafan1 \
  --input-fps 30 --output-fps 50 --workers 12
```

数据验收：

- 转换结果为 40 段，总时长约 2.45 h，输出 50 Hz。
- 核对米 / 弧度、关节顺序及模型一致性。原始 CSV 四元数为 `xyzw`，转换后的 NPZ 和 MuJoCo 使用 `wxyz`，不要混用。
- 检查静态姿态、舞蹈、跳跃、起身等代表动作的参考回放。
- 运行仓库已有 FK、解析奖励、状态读写、buffer 与数据转换测试。

## 5. 单卡训练参数

优先按本机检测到的约 48 GiB 显存规划，从小规模短跑逐步升到正式批量。

| 参数 | 本机正式配置 | 节省显存配置 | 说明 |
| --- | --- | --- | --- |
| 仿真环境数 | 4096 | 2048 | 首次短跑先用 1024 |
| 策略想象批量 | 4096 | 2048 | OOM 时优先减半 |
| 想象长度 | 32 | 32 | 首轮保留方法关键设置 |
| 世界模型窗口 | 8 | 8 | 自回归多步拟合 |
| 世界模型训练批量 | 10 批 × 2048 | 10 批 × 1024 | 每次更新的设置 |
| Replay | 1000 步 / 环境 | 1000 步 / 环境 | 暂不改采样机制 |
| UTD | 0.4 | 0.4 | 同时记录真实数据量和更新量 |
| 学习率 | 2e-4 | 先沿用 2e-4 | 调整时作为独立实验记录 |
| 折扣 / GAE | γ=0.99，λ=0.95 | 相同 | 保留 critic |
| Critic 更新 | 5 epoch × 4 minibatch | 相同 | 与主仓库默认配置一致 |
| 精度 | FP32 + TF32 | 相同 | 数值对拍按测试要求关闭 TF32；bf16 后续单独评估 |
| 编译 | 开启 `torch.compile` | 相同 | 首次编译和稳定吞吐分别计时 |

网络先保持原规模：世界模型为 2048×3，策略编码器 / 解码器为 2048/1024/512/256，latent 为 32。首轮不同时缩网络和改算法。

参数依据：[论文附录 Table A.4/A.5](https://arxiv.org/pdf/2610.28480)、[主仓库配置](https://github.com/CuboiLeo/SuperMimic-Reproduced/blob/d9be385b3eeb13a638fb33fb200d3bfd9be9839f/src/supermimic/config.py)。

上游日志曾记录 LAFAN1 的 4096 批实验显存约 24 GB，但这不是本机测量。建议本机正式运行峰值先控制在 38–40 GiB 内，为编译缓存、分配器与桌面留出余量。若实际显存仅能按 24GB 使用，则采用节省显存配置，并在结果中披露批量差异。

## 6. 实施顺序与验收

### 阶段一：环境、数值和短跑

依赖和数据就绪后，先运行已有测试与基准：

```bash
env -u PYTHONPATH uv run pytest tests -q

env -u PYTHONPATH uv run python scripts/bench_sim_speed.py \
  --num-envs 1024 --steps 300

env -u PYTHONPATH uv run python scripts/bench_imagination.py \
  --batch 1024 --horizon 32

env -u PYTHONPATH uv run sm-train --run-name smoke4090 \
  --data.npz-dir data/npz/lafan1 --data.limit 3 \
  --env.num-envs 1024 --policy-trainer.batch-size 1024 \
  --wm-trainer.batch-size 1024 --schedule.total-iterations 500 \
  --schedule.checkpoint-interval 500
```

通过条件：

- 仿真实际在 GPU 上运行，图捕获和编译正常。
- loss、梯度和动作均有限，没有 NaN 或持续仿真异常。
- 世界模型 8 步预测误差随训练下降。
- 能保存、重载检查点，并在真实仿真中评测。
- 记录整个进程的显存峰值、仿真吞吐、世界模型更新耗时和策略更新耗时。

在编译完成后的稳定阶段测速度，再决定正式批量和时长。不要把首次编译时间直接当成每次迭代耗时。

### 阶段二：LAFAN1 两条实验线

**A：默认观测线。** 不开启锚点额外观测，重点核对论文定义和真实差距。

```bash
env -u PYTHONPATH CUDA_VISIBLE_DEVICES=0 uv run sm-train \
  --run-name lafan_paper_s0 --seed 0 \
  --data.npz-dir data/npz/lafan1 \
  --env.num-envs 4096 --env.replay-capacity 1000 \
  --policy-trainer.batch-size 4096 --policy-trainer.horizon 32 \
  --wm-trainer.batch-size 2048 --wm-trainer.window 8 \
  --schedule.updates-per-env-step 0.4 \
  --schedule.checkpoint-interval 4000 --schedule.max-hours 6
```

**B：工程效果线。** 独立训练一份开启锚点观测的策略，用于先获得稳定动作，并量化额外观测的作用。

```bash
env -u PYTHONPATH CUDA_VISIBLE_DEVICES=0 uv run sm-train \
  --run-name lafan_anchor_s0 --seed 0 \
  --data.npz-dir data/npz/lafan1 --env.anchor-obs \
  --env.num-envs 4096 --env.replay-capacity 1000 \
  --policy-trainer.batch-size 4096 --policy-trainer.horizon 32 \
  --wm-trainer.batch-size 2048 --wm-trainer.window 8 \
  --schedule.updates-per-env-step 0.4 \
  --schedule.checkpoint-interval 4000 --schedule.max-hours 6
```

A/B 输入维度不同，使用独立 run，不能直接互相续训。6 h 是首轮资源上限，不是收敛时间预测；若提前出现平台，应先诊断。

若 OOM，先将策略批量降到 2048；必要时再降低环境数和世界模型批量。优先保留 H=32、critic 和模型规模，并记录所有差异。

### 阶段三：整段评测与视频

以下以 B 线为例，A 线替换检查点路径即可：

```bash
env -u PYTHONPATH uv run python scripts/eval_benchmark.py \
  --ckpt logs/lafan_anchor_s0/ckpt_latest.pt \
  --npz-dir data/npz/lafan1 --num-envs 64

env -u PYTHONPATH uv run python scripts/play.py \
  --ckpt logs/lafan_anchor_s0/ckpt_latest.pt \
  --clips dance1_subject1
```

评测统一为：从每段首帧开始播放至结束，摩擦 1.0，关闭域随机化与观测噪声，使用确定性策略。该设置来自[论文 Appendix F](https://arxiv.org/pdf/2610.28480)；LAFAN1 长段评测与论文曲线的具体对应仍需核对。

至少记录：

- 40 段按段平均归一化回报、按步加权回报。
- 失败数、失败动作名称和终止帧。
- 六个跟踪奖励分项，以及根部 xy / yaw 漂移。
- 真实仿真回报与想象回报是否同步改善。
- 环境步数、世界模型更新数、策略更新数、GPU 小时；评测耗时单列。
- 舞蹈、跳跃、起身、跑步的参考动作与机器人对照视频。

工程线目标可设为平均回报 ≥0.82、失败尽量达到 0/40。**即使 B 线达标，也只能报告额外观测下的工程复现；A 线需要单独给出结果。**

两仓库的 `iteration` 定义不同，不能直接比较相同迭代数。主仓库对论文训练日程的解释也需核对，因此应以实际环境步数、更新次数和时间共同描述预算。

### 阶段四：重复实验和机制验证

基础结果稳定后，再开展：

1. 成功配置运行 seed 0、1、2，报告均值和波动。
2. 比较 H=16 / 32，以及有 / 无 critic，验证短视野训练机制。
3. 对世界模型保留独立仿真窗口，评测开环多步误差，避免只看拟合数据。
4. 如果默认观测出现公开日志中的漂移平台，优先核对目标特征、朝向语义、奖励坐标系和评测长度。

若想象回报上升但真实仿真不改善，应检查策略是否利用了模型误差，以及终止头、奖励头和仿真的一致性。此时继续堆训练时间通常不能替代诊断。

## 7. BONES-SEED 扩展条件

LAFAN1 闭环稳定后，采用 [BONES-SEED G1 数据](https://huggingface.co/datasets/bones-studio/seed)，按 1 h → 7 h → 40 h → 全量逐级扩展。

需要提前解决两个问题：

**数据清单不完全一致。** 论文过滤后为 129,514 段 / 264.56 h；主仓库为 129,943 段 / 263.75 h。必须冻结并保存过滤清单，解释差异后再比较全量指标。[主仓库数据说明](https://github.com/CuboiLeo/SuperMimic-Reproduced)

**磁盘空间需要规划。** 上游日志记录压缩包约 23.5 GB，紧凑 fp16 动作库约 6.7 GB；解压 CSV、完整刚体 NPZ、缓存和检查点会产生额外占用。本机目前剩余 136 GiB，不宜同时无限保留所有中间格式。

建议预留额外 200–300 GiB 工作空间，或实现分批转换、验证后清理中间数据。这个数字是规划预算，应根据第一批转换的实际文件大小重新估算。

训练使用紧凑动作库，优先保留 4096 环境；全量阶段策略批量可以从 2048 起测。对子集评测得到的高分，只能报告为子集结果；全量结论必须经过全量评测。论文主基准测量的是训练动作覆盖率，要研究泛化需另设未见动作划分。

## 8. 时间与空间预算

| 阶段 | 初始预算 | 性质 |
| --- | --- | --- |
| 环境适配与 GPU 验证 | 0.5–2 h，下载和排错另计 | 工作安排，非实测耗时 |
| 数据、数值测试和短跑 | 约半天 | 首次编译与问题修复可能延长 |
| LAFAN1 A/B 首轮 | 每线最多 6 GPU-h，合计最多 12 GPU-h | 资源上限，非达标承诺 |
| 首轮闭环交付 | 预留 1–2 天 | 环境、曲线、评测 JSON 和视频 |
| 多种子、消融、全量 | 短跑后重新估算 | 暂不作精确速度预测 |
| 环境、缓存和 LAFAN1 首轮日志 | 预留 25–40 GiB | 需控制检查点留存 |

全量算时按本机稳定阶段的收集与更新耗时推算，编译、评测分别统计。不能把 H100 的“3 小时”或其他仓库的 5090 成绩直接换成本机保证。

## 9. 推荐执行决策

先采用 **mjlab 主线 + CUDA 12 兼容依赖 + LAFAN1 40 段 + A/B 观测对照**。第一项交付应是：本机环境锁文件、短跑记录、40 段评测、曲线和动作视频。

在这个基础上，再决定是否扩展到全量 BONES-SEED、补齐机制消融，或等待官方代码后做严格对齐。当前最值得先完成的是一个可重跑、可评测、差异有记录的单卡闭环。
