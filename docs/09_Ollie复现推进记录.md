# 指定 Ollie：链路实施与验证记录

2026-10-23，用户要求将 `video/ollie.mp4` 的方案实际打通，持续推进到可查看的物理仿真视频；随后明确授权直接下载 SMPL-X 等所需模型和依赖，无需逐项确认。本文持续追加实际结果，方案依据见 [视频分析](07_Ollie视频分析与实施方案.md)。

## 实施约定

- 目标保持 29 DoF G1 与被动滑板的真实连续物理执行，SuperMimic 人板联合扩展为目标算法。
- 人体前端、GMR 和板追踪使用独立环境，不升级系统驱动，不破坏已验证的平地训练环境。
- 运动学参考、用于物理可行性检查的轨迹控制、学习策略分别命名；阶段调试视频不冒充最终复现。
- 正常重力、板无主动关节 / 隐藏推进或吸附；最终完整回合中不在起跳、腾空、落地之间重置。
- s=1.5 慢放为用户估计，保留时间倍率与米制尺度假设，人体 / 板 / 接触必须共用时间和世界坐标。
- 每批代码测试完成后使用中文提交并推送 `sxh-kk/SuperMimic_Recurrence`；模型、输入视频、派生数据、运行日志和 MP4 留在忽略目录。

## 第一批：实际部署与独立组件

已开始并行实施：

1. **视频人体恢复**：固定克隆 GVHMR，独立 Python 3.10 / Torch 2.3 CUDA 12.1 环境。公开模型下载与固定版本 / 哈希记录在本机；SMPL-X NEUTRAL `.npz` 已下载且哈希匹配。为保留滑板交互，禁用普通脚锁地面后处理；不依赖 SMPL-H 替代。具体执行见文档 10。
2. **被动板物理场景**：自由板、四个无驱动轮、分段板头尾碰撞形状，与原 G1 组合；优先原地 Ollie，不增加暂时无关的 truck 转向。属于根据任务新建的简化物理模型，不能标成完整 HUSKY。具体检查见文档 11。
3. **联合状态 / 参考契约**：机器人原 71 维状态加自由板与四轮的 21 维，名义状态 92 维；按模型地址映射，保持原平地代码契约。参考记录显式物理时间、视频时间、阶段、接触和置信度。见文档 12。
4. **板图案二维追踪**：独立 OpenCV 环境，对人工给定的少量板面图案角点做双向光流 / RANSAC 传播；对失败保留缺失与置信度，不输出虚假的全帧可靠三维轨迹。见文档 13。

本段是实施开始时的状态，尚未声称人体重建、G1 重定向、联合训练或最终动作复现成功。后续以各验证结果追加为准。
