# 指定网络视频动作：开源项目调研与接入方案

调研日期：2026-10-23。用户确认素材为“网络上的单人视频”。本文件记录方案与源码核对结果，尚未安装视频重建依赖、处理用户视频或验证陌生动作成功率。当前 LAFAN1 训练继续运行。

## 推荐方案

第一版采用 **GVHMR → GMR → 本项目 G1 动作格式 → 冻结 SuperMimic 策略测试**。理由是 GVHMR 提供时序世界坐标人体运动，GMR 已有读取其结果并重定向到 G1 的接口；我们主要补齐时间轴、模型匹配、质量检查和结果视频。此选择基于接口衔接与当前需求，不是声称它在所有视频上的精度最高。

```text
原始视频 / 链接 + 指定起止时间
    ↓ 分镜、目标人物确认、按时间戳统一到 30 fps
GVHMR：视频 → 世界坐标 SMPL-X 人体运动
    ↓ 人体回放及二维重投影检查
GMR：人体运动 → G1 29 DoF 根位姿与关节角
    ↓ 关节名、坐标、单位、帧率及脚底接触检查
本项目 CSV → 50 Hz NPZ（使用本机 G1 模型重新做 FK）
    ↓ 冻结本轮训练权重；视频动作独立保存，不加入训练集
整段物理跟踪评测 + 原视频 / 人体重建 / G1 参考 / G1 实际四路对照
```

网络视频需先判断静态机位或运镜。有剪辑就拆成独立片段，每段重新初始化相机和人体轨迹，不把镜头切换当作人体瞬移。第一段建议 5–10 秒，单人全身和双脚清晰、平地、没有明显遮挡；这是本项目的工程起步建议，不是上游模型的硬性输入限制。

## 开源项目与相关工作

| 项目 / 工作 | 已核实能力与开放状态 | 本项目定位 |
| --- | --- | --- |
| [GVHMR](https://github.com/zju3dv/GVHMR)，SIGGRAPH Asia 2024 / TPAMI 2026 | 官方代码与预训练权重可得；恢复世界坐标时序人体运动，输出 SMPL-X 参数；当前 demo 默认 SimpleVO，静态机位可跳过相机运动估计 | 主选视频前端；先验证短片，不直接承诺本机显存或速度 |
| [GMR](https://github.com/YanjieZe/GMR)，ICRA 2026 | MIT 源码，CPU 上做运动重定向；内置 G1 29 DoF，官方脚本能读取 GVHMR 输出 | 主选人体到 G1 重定向；运动学参考仍需物理跟踪验证 |
| [BeyondRetarget](https://github.com/bear-ty/BeyondRetarget)，2026 | 已公开推理代码、权重下载与 G1 等机器人配置；直接由 RGB 预测根轨迹、关节和接触，再做平滑 / 足部 IK；CC BY-NC 4.0 | 固定机位、小范围运动的对照路线；当前公开 base 版明确不支持移动机位和大范围全局轨迹，不作为一般网络视频主线 |
| [GEM-X](https://github.com/NVlabs/GEM-X) + [SOMA Retargeter](https://github.com/NVIDIA/soma-retargeter) | 2026-10-21 更新的 GEM-X 已有 Body Motion 代码与官方权重；Retargeter 内置 G1，包含脚接触处理 | 第二阶段对照；当前公开文件接口仍需桥接，见下文 |
| [VideoMimic](https://github.com/hongsukchoi/VideoMimic)，CoRL 2025 | 已开放 real-to-sim、仿真和初步 sim2real 代码；同时重建人体、场景并学习场景相关控制 | 若目标包含楼梯、坐椅或障碍物，再参考其场景链路；当前平地策略不能仅靠新参考动作完成这些交互 |

GVHMR 当前的静态机位参数为 `-s/--static_cam`，DPVO 为可选项；以[当前 demo 源码](https://github.com/zju3dv/GVHMR/blob/main/tools/demo/demo.py)为准，避免沿用旧教程中“必须先装 DPVO”的假设。GMR 已有 [GVHMR → G1 脚本](https://github.com/YanjieZe/GMR/blob/master/scripts/gvhmr_to_robot.py)。

BeyondRetarget 的公开 base 限制由其[项目页](https://bear-ty.github.io/Beyondretarget_page/)和[仓库说明](https://github.com/bear-ty/BeyondRetarget)明确给出。其 [G1 配置](https://github.com/bear-ty/BeyondRetarget/blob/main/config/robot/g1.yaml)是 29 DoF；[导出代码](https://github.com/bear-ty/BeyondRetarget/blob/main/lib/util/robot_export_utils.py)虽能写类似本项目的 body NPZ，但使用自己的 XML / body 顺序，不能未经校验直接复用，仍应转根位姿与关节并用本机模型重建 FK。

其他可参考前端：

- [WHAM](https://github.com/yohanshin/WHAM)，CVPR 2024：世界坐标、接触感知运动恢复；官方全局流程依赖相机估计，旧环境适配成本较高，作为人体重建的交叉检查。
- [SLAHMR](https://github.com/vye16/slahmr)，CVPR 2023：联合优化人体与相机，处理复杂轨迹，但组合 PHALP / SLAM / HuMoR 的链路较重。
- [PromptHMR](https://github.com/yufu-wang/PromptHMR)，CVPR 2025：适合更复杂的遮挡或多人场景；依赖较多，当前单人短片不优先引入。
- [DuoMo](https://github.com/facebookresearch/DuoMo)，CVPR 2026：世界坐标运动恢复的新候选；公开流程默认静态机位，不包含现成 SLAM，运镜视频仍要补相机运动。
- [SONIC](https://github.com/NVlabs/GR00T-WholeBodyControl) / [ProtoMotions](https://github.com/NVlabs/ProtoMotions)：可借鉴重定向、数据处理或作为另一控制器的对照。使用这些控制器得到的结果须标明来源，不能当作本项目 SuperMimic 策略的结果。

## 用户最终需要提供什么

必需内容：

1. 可访问的视频链接或本地视频文件，优先保留清晰原版。
2. 要测试的起止时间，例如 `00:12–00:20`；首次先选一个连续短镜头。
3. 指定目标人物，并说明是否镜像、慢放或变速；不知道时先由前处理检查。

有则更好的信息：人物身高、地面已知尺寸、是否希望严格跟踪位移 / 转向，还是先只看动作姿态。这些信息有助于检查单目尺度。缺少时可以先用模型估计，但不能把估计的米制轨迹当作准确测量。第一版无需动捕服、深度相机或手工三维标注。

对于人物被长期裁掉下半身、快速剪辑、严重遮挡、频繁变焦或需要椅子 / 楼梯支撑的视频，应先换片段或明确增加场景恢复工作；不能默认把缺失的接触条件交给平地策略解决。

## 需要补充的资源和环境

- GVHMR 按官方流程下载 GVHMR、人体特征 / 关键点和检测模型权重。还需取得 SMPL / SMPL-X 体模；GVHMR 与 GMR 对文件格式和目录的要求不同，按各自安装文档准备。[GVHMR 安装与资产](https://github.com/zju3dv/GVHMR/blob/main/docs/INSTALL.md)、[GMR 数据准备](https://github.com/YanjieZe/GMR#data-preparation)。
- SMPL / SMPL-X 文件需要按官方注册和条款获取，不随本仓库分发。GVHMR 自有源码是教育 / 研究 / 非营利用途许可，GMR 自有源码是 MIT；各自依赖、权重和体模保留原许可，不能把整个视频链路统一重标为 MIT。[GVHMR 许可](https://github.com/zju3dv/GVHMR/blob/main/LICENSE)、[GMR 许可](https://github.com/YanjieZe/GMR/blob/master/LICENSE)。
- 建独立的视频重建环境和 GMR 环境。GVHMR 官方起点为 Python 3.10、Torch 2.3.0 + CUDA 12.1；与当前训练 Python 3.12 / Torch 2.14.1 环境分离。默认先用 SimpleVO；只有确有收益再单独处理 DPVO 编译。[依赖文件](https://github.com/zju3dv/GVHMR/blob/main/requirements.txt)。
- 第三方源码与其环境放在已忽略的 `references/` 下，视频 / 权重 / 中间动作在 `data/` 下，机器日志 / MP4 在 `logs/` 下；只提交自写适配代码和本目录 Markdown。

本机报告约 48 GiB 物理显存和 188 GiB RAM，当前训练进程约占 20 GiB 显存，系统可用内存仍约 157 GiB。资源方向适合尝试这条离线链路，但尚未实测这些前端，不能保证全部模型同时装入 GPU，也不给无依据的耗时 / 最低显存数字。按检测、重建、重定向、物理评测顺序运行并释放前一阶段模型；首片低 batch、短片实测显存。当前训练期间只做调研和 CPU 前处理；首轮训练结束后再安排 GPU 视频推理与评测，保持本轮时间口径。

## 本项目需要新增的适配内容

以下均为待实现模块，不代表已经完成或通过运行：

| 模块 | 工作内容 | 验收 |
| --- | --- | --- |
| 视频前处理 | 读取时间戳、分镜、裁时间段、明确镜像和倍速，真实重采样为 30 fps，保存来源 / 时长 / 帧率 | 前后动作时长一致，固定输出帧率，无镜头跳变混入同段 |

### 已核实的上游接口细节

1. **时间轴不能只改 FPS 标签。** GVHMR 当前 demo 逐帧复制输入，却按 30 fps 写出；60 fps 或变帧率视频若直接输入，会改变动作时长。先按时间戳真正重采样到 30 fps，再推理，并把 30→50 Hz 的转换独立记录。[源码](https://github.com/zju3dv/GVHMR/blob/main/tools/demo/demo.py#L77)。
2. **GMR 示例有帧和速度约束细节。** 当前 `gvhmr_to_robot.py` 目标 fps 为 30，非 loop 分支先递增索引再处理，会漏第 0 帧；自写 headless 循环须覆盖全部帧。其 `.pkl` 保存 `fps/root_pos/root_rot/dof_pos`，根四元数保存时转为 xyzw。[导出脚本](https://github.com/YanjieZe/GMR/blob/master/scripts/gvhmr_to_robot.py)。
3. **显式设置速度限制。** 当前 GMR 构造函数的 `use_velocity_limit=False`，不能只依据 README 假定已开启；接入时明确打开，并复核本机模型的角度 / 速度。约束也不能保证动态平衡或力矩可行。[构造函数](https://github.com/YanjieZe/GMR/blob/master/general_motion_retargeting/motion_retarget.py)。
4. **本地标准输入**为无表头 36 列：根位置 xyz（米）＋根四元数 xyzw＋29 关节角（弧度）；关节顺序以 `src/supermimic/data/motion_convert.py` 的 `G1_JOINT_NAMES` 为准。NPZ 则使用 wxyz 刚体四元数，由本机模型计算位置和速度。不要把 MuJoCo qpos 的 wxyz 直接写进 CSV。
5. **转换不是物理修复。** 本地 CSV→NPZ 只做重采样、求速度和 FK；不自动消除穿地、脚滑或不可行动作。尤其环境 reset 会把关节裁到 soft limits，而参考库目标不同时修改，超限可能导致首帧不一致；必须在进入策略前检查。

## 分阶段测试与结果口径

第一阶段：选一个 5–10 秒简单短片，先审查人体重建。看脚是否跟地面一致、肢体是否翻转、轨迹是否在运镜时漂移。只有单目视频时，没有三维真值，不能宣称恢复了准确的三维轨迹；可报告二维重投影、时间连续性和可视检查结果。

第二阶段：只看 G1 运动学参考。核对关节、朝向、根高度、双脚和动作速度，确认不是纯粹“能播放”。如需要平滑或降速，保留原始版本并记录参数；降速结果不能冒充原速跟踪。

第三阶段：冻结本轮检查点，**先做未针对该视频训练的直接测试**。新视频放在 `data/npz/video_eval/<case>/`，不混入 `data/npz/lafan1/`。固定首帧开始、关闭评测噪声和随机化，比较 G1 参考与策略物理执行。可以复用本地 `eval_benchmark.py`、`diag_drift.py`、`play.py`，之后补统一 MP4 导出。

应同时报告：完整片段完成比例、失败时刻、整段分母归一化回报、参考与执行的根 XY / yaw 漂移，以及接触窗口脚滑等质量指标。当前 benchmark 按实际执行步数平均，必须另外核对完整长度口径，不能靠提前失败的短段平均高分判断成功。原视频与机器人身体比例不同，跟踪量化指标主要在同一 G1 参考与 G1 执行之间比较。

第四阶段：若参考合理但直接跟踪失败，再考虑针对视频微调、扩充动作库或独立 anchor 观测分支。先保留零样本结果，微调后另命名记录；已经用视频训练的结果属于适应后表现。当前仅用 LAFAN1 40 段训练，陌生动作成功率未知；`anchor_obs=False` 也可能限制长段全局位置 / 朝向纠偏，不能直接开启 anchor 并加载原目标维度的策略权重。

最终交付为：原片段、人体重建、G1 参考动作、G1 策略执行的对齐画面；单独保留失败时刻；对应的动作数据、源版本、模型 / 检查点哈希和 Markdown 结果。四路视频是待补充的导出功能，当前已有的是交互式回放。

## GEM-X / SOMA 的第二路线

GEM-X 的时序 Body Motion 与逐帧 Body Pose 是不同任务；应使用前者做机器人运动参考。其[官方权重](https://huggingface.co/nvidia/GEM-X)已开放；[推理文档](https://github.com/NVlabs/GEM-X/blob/main/docs/DEMO.md)描述单人主轨迹、30 Hz、最长 60 秒以及背景 / 静态 / 外部相机旋转模式。

当前公开 GEM-X 推理结果是 `.pt`，SOMA Retargeter 入口则为 SOMA base BVH；截至调研未找到可直接复用的 GEM-X `.pt`→该 BVH 的命令，需要验证或新增骨架桥接。其 G1 manifest 使用 29 DoF XML。[Retargeter](https://github.com/NVIDIA/soma-retargeter)、[G1 manifest](https://github.com/NVIDIA/soma-retargeter/blob/main/soma_retargeter/assets/robotics/unitree/g1/manifest.json)。

SOMA Retargeter 的 CSV 使用 `Frame,root_translateX...` 表头、厘米、xyz Euler 度和关节角度，并且 CSV 不自带 fps。[CSV 源码](https://github.com/NVIDIA/soma-retargeter/blob/main/soma_retargeter/io/csv.py)。**本地已存在处理这些单位的 BONES 分支**，无需重复实现同一套转换；但必须确认输出关节列名和顺序符合本地 `*_joint_dof` 契约，必要时按名重排，并核对世界轴、fps 和 G1 模型。

该路线需要独立的 GEM-X 与 Newton / Warp 重定向环境。官方 GEM-X 模型卡列 A100 80 GB 参考硬件，没有给出最低显存；这既不证明 4090 无法运行，也不能保证本机必过。若后续尝试，先短片、小 batch，实测峰值。源码、权重和资产的条款不同，按[各自归属](https://github.com/NVlabs/GEM-X/blob/main/ATTRIBUTIONS.md)保留。

## 实施顺序

1. 当前 LAFAN1 首跑按用户最新要求，累计约 1 小时保存并停止；这不等于完成全部基线训练。保留该检查点用于后续初步测试。
2. 收到视频链接 / 文件与时间段后，检查片段条件和时间轴。
3. 单独部署 GVHMR / GMR 与所需体模，固定实际使用的代码提交和权重哈希，新增上表的适配模块。
4. 先通过人体与 G1 参考验收，再跑冻结策略的直接测试。
5. 根据失败归因决定前端对照、数据扩充或微调；GEM-X / BeyondRetarget 保留为有针对性的第二路线。

本次只形成调研与实施方案，不将“代码开放 / 接口存在”写成本机已跑通或陌生视频已跟踪成功。
