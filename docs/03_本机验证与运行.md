# 本机验证与运行

所有命令从项目根目录执行。先完成 `02_本机环境适配.md` 中的依赖安装。

## 分层验证

```bash
env -u PYTHONPATH -u PYTHONHOME uv run --locked python scripts/local/check_runtime.py

env -u PYTHONPATH -u PYTHONHOME PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 uv run --locked pytest -q \
  tests/test_g1_fk.py \
  tests/test_world_model.py::test_state_spec_identity_and_errors \
  tests/test_imagination.py::test_gae_targets_match_hand_computation

env -u PYTHONPATH -u PYTHONHOME uv run --locked python scripts/local/smoke_train.py
env -u PYTHONPATH -u PYTHONHOME uv run --locked python scripts/local/smoke_train.py --compile

# 正式网络规模、4096 环境/策略批量、H=32、replay=1000，仍使用临时合成动作。
env -u PYTHONPATH -u PYTHONHOME uv run --locked python scripts/local/smoke_train.py --full-size

# 正式批量的编译路径；24 步会完成 3 次更新。
env -u PYTHONPATH -u PYTHONHOME uv run --locked python scripts/local/smoke_train.py \
  --full-size --compile --steps 24
```

- 预检实际执行 PyTorch 前向 / 反向与 Warp CUDA 内核，不将“能看到显卡”视为完成。
- 数值基线预期 7 个用例，CUDA FK 对照不能跳过。
- 合成冒烟使用系统临时目录，不写入真实 `data/npz/lafan1`；退出后自动清理。
- 冒烟缩小网络与批量，检查仿真、replay、世界模型更新、策略与 critic 更新、检查点保存与恢复。
- `--full-size` 保留标准网络、4096 环境 / 策略批量、H=32 和 replay=1000；用于验证正式批量的基本显存可行性，仍不代表真实数据训练收敛。
- 每次冒烟额外计算 8 步开环预测误差并检查有限值。原训练日志在 replay 不超过 2048 行时不计算该诊断，显示的 `nse8 nan` 表示该日志项未计算，不能据此判定预测含 NaN；以冒烟最后显式校验结果为准。
- 检查点验证为同一实例加载权重并核对恢复结果；不将该检查写成新进程断点续训验证。
- `--compile` 单独验证编译路径；首次编译时间计入该次冒烟耗时。
- 合成动作和小模型仅验证软件管线，不代表论文精度、动作成功率或正式批量显存。

## 4090 运行预设

真实数据准备好后使用：

```bash
# 默认观测，保留论文主要批量；首次运行先观察显存。
bash scripts/local/train_4090.sh lafan

# 节省显存配置。
bash scripts/local/train_4090.sh lafan-lowmem

# 工程观测对照，必须独立 run，不和默认观测共用权重。
bash scripts/local/train_4090.sh lafan --run-name lafan_anchor_s0 --env.anchor-obs

# 全量紧凑动作库，策略批量 2048 起步。
bash scripts/local/train_4090.sh bones

# 额外参数可覆盖预设，例如仅做短跑。
bash scripts/local/train_4090.sh lafan --env.num-envs 1024 \
  --policy-trainer.batch-size 1024 --schedule.total-iterations 500
```

所有预设保留 H=32、replay=1000 步/环境，单次时间上限默认 6 h，可通过参数修改。预设不自动下载数据、不自动开启额外锚点观测。

## 实际验证记录

### 2026-10-23：已完成的基础验证

- PyTorch `2.14.1+cu126` GPU 前向 / 反向通过。
- Warp `1.18.0+cu12` 的实际 CUDA 内核编译和执行通过；输出 Toolkit 12.9、Driver 12.8，当前组合实际可用。
- CUDA 识别的可用设备总显存约 47.36 GiB；nvidia-smi 报告物理总量 49140 MiB，二者统计口径不同。
- 数值基线：7 passed，0 skipped，12.67 s，包含 CUDA FK 对照。
- 初版小规模 eager 冒烟：48 步、13 次更新，36.6 s（包括首次物理内核编译），Torch 分配峰值 0.03 GiB；三个模型均更新，状态有限，检查点权重重载通过。
- 新增脚本 Ruff 检查、shell 语法和三个运行预设的 `--help` 均通过。
- TorchScript 弃用提示来自上游依赖，为 FutureWarning，未导致检查失败。

### 2026-10-23：编译、正式批量与额外观测检查

| 测试 | 环境 / 策略批量 | H | 步数 / 更新数 | 用时 | Torch 分配峰值 | 最终 8 步误差 | 结果 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 小模型，编译模式 | 16 / 16 | 8 | 48 / 13 | 181.6 s | 0.10 GiB | 0.652924 | 通过 |
| 标准网络，非编译 | 4096 / 4096 | 32 | 48 / 13 | 34.4 s | 16.97 GiB | 0.343513 | 通过 |
| 小模型，额外锚点观测，非编译 | 16 / 16 | 8 | 48 / 13 | 11.3 s | 0.03 GiB | 0.652479 | 通过 |
| 标准网络，编译模式 | 4096 / 4096 | 32 | 24 / 3 | 217.9 s | 17.10 GiB | 1.586833 | 通过 |

上述检查均验证了三个模型参数实际更新、状态与 8 步误差有限、检查点权重重载正确。标准网络规模为世界模型 8.82M、策略 8.89M、critic 0.235M 参数。

注意：

- 用时包含该次脚本启动和初始化；编译模式包含首次 Torch 编译成本，不能据此推算稳定训练速度。
- Torch 分配峰值来自 `torch.cuda.max_memory_allocated()`，不包含全部 Warp / CUDA 外部显存分配，不能直接当作进程总显存。
- 使用单段临时合成动作；关闭观测、重置噪声和域随机化，动作噪声保持默认值。这些检查不包含完整动作库，不代表真实训练收敛或论文跟踪成绩。
- 第一次额外进程显存采样启动较晚，未捕获已结束的非编译运行；样本数为 0，该次采样不计入显存结论。随后对正式批量编译检查进行了同期采样。
- 标准网络编译检查的 `train_ret nan (n=0)` 表示 24 步内没有已结束回合，未计算回合回报；状态、模型参数及显式 8 步预测误差检查均通过。不能把该短跑的训练回报当作动作跟踪评测。

标准网络编译检查同时以约 0.5 秒间隔查询本进程的 nvidia-smi 显存，434 个样本、监测 229.6 s，观察到最高 **19958 MiB，约 19.49 GiB**。该进程统计包含比 Torch 分配器更广的显存占用；离散轮询可能漏掉短时尖峰，不视为精确连续峰值。

结论：当前 4090 / R570 / CUDA 12 软件链已通过标准网络、4096 环境、4096 策略批量、H=32 的基础运行验证。实测没有出现 OOM，且可用显存有余量。真实 LAFAN1 / BONES-SEED 动作库、完整域随机化和长期训练的峰值与收敛表现仍需后续实测。
