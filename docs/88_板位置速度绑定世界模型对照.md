# 88｜板位置速度绑定世界模型对照

本轮是 SuperMimic 人板世界模型的一次离线表示对照，只检验[78已指出的位置速度独立修正问题](78_接触世界模型位置速度一致性诊断.md)。不采集新动作、不训练 actor、不执行 BPTT、不运行物理仿真。当前完整 Ollie 仍 FAILED，任何本轮指标改善都不解锁板 BPTT。

## 正式训练前固定的唯一实验

两臂为 `legacy` 与 `trapezoid`，都使用[73](73_显式足板接触监督世界模型对照.md)的状态损失和真实正负配对损失；两臂辅助损失均为0。唯一差异是板根位置的解码公式：

```text
legacy:    v' = 原速度解码；p' = p + dt*v' + R_heading*dp
trapezoid: v' = 原速度解码；p' = p + .5*dt*(v + v')
dt = .02 s
```

`v'`只能来自模型自己的预测，不能输入真实未来速度。梯形分支忽略原板3个独立dp输出；仍保留 state92、canonical94、delta90与512×512×512主网络及辅助头，机器人71维、板转角/角速度/被动四轮解码逐值复用原实现。没有改旧state.py、learning.py、contact_learning.py、73脚本或任何物理资产。

固定 seed73、新随机共同主网络/辅助头初值、batch64、每臂500次、Adam lr `2e-4`、梯度范数上限1、H8自由递推、轮误差权重 `.05`、配对权重1、原42/73的24SI响应尺度。每次由同一CPU RNG生成窗口/配对批次交给两臂，批次和初值都需逐Tensor/哈希相同；不从73已训练权重热启动，不调权重/seed/数据/结构，不做额外网格。500次批次哈希应复现73的 `ae98ebdb4fa5c43816595163fb09d13c57833cd16d54d3b50a81ad6d0b0703bb`；共同主网络/头初值哈希应为 `b60eef34918c3a3675fd86ef17d9d43a62ead020e377bac365f81bd2f78e13b8`。

唯一数据为 `logs/ollie_mu09_responses_01/paired_responses.npz`，SHA256 `e46105385a51b5dc151064bbdff477e854b4ade155efb53963d737e7f6437e8b`；源65实际完整轨迹SHA256 `8b602ad7f88266ba831c71df6c0f25bc84366a3af13427166e559f45d4470cb7`。这是显式足板摩擦μ=.9的局部热状态数据，不能与当前μ=.6的原生物理候选混为同一模型。

## 检查点与兼容性契约

新增 `BoardPositionCodecSpec` 只在 `super.integrate` 后替换板XYZ。`PositionCodecContactWorldModel` 必须明确指定mode，persistent int64 `_position_codec_id` 区分两种语义；新schema为 `supermimic.ollie.position_codec_wm.v1`。加载helper必须同时核schema、两处codec元数据（mode/id/dt/explicit/state/delta维数）与buffer；raw `load_state_dict` 的pre-hook也拒绝缺失或错mode的buffer，即使strict=False。旧模型strict加载新权重因extra buffer拒绝；新模型加载旧权重也拒绝。未修改旧加载器或默认模型含义。

必要CPU契约覆盖：legacy逐值一致；梯形数值、原其余字段不变；板位置对dp通道梯度为0、对预测速度梯度非0且有限差分一致；非法dt/关闭explicit/未明确mode拒绝；新旧及错mode/篡改元数据检查点拒绝；weights_only读回。两臂辅助头不得更新。
