# Ollie 目标、视野与真实起跳动量诊断

## 结论与最小下一步

当前失败不能仅归因于H8较短，也不能因单步根VZ梯度有效就认为已有可执行的起跳目标。实际存在三类不同问题：**接触几何尚未实现踩尾、参考空中联合COM不符合无外力运动、当前优化目标没有直接检验起跳/接板的动量与接触顺序**。此外H8无critic/终值有明确短视风险，世界模型的板梯度仍不可靠。

**最小下一步是先给正在修复的tail可达参考增加联合COM飞行一致性检查，检查不过不启动下一轮actor。** 以真实质量和刚体运动学计算机器人+板的联合COM；在无地接触段检查水平动量近似恒定、竖直速度按重力下降。修正只应落在明确标注的不确定参考拟合上，不能修改仿真重力、加板力或把参考当视频实测真值。随后先从已有准备前缀做原生连续评测，再决定短期动量课程和视野/critic扩展。

本次没有扩大H32、没有训练critic、没有改变策略残差范围或物理参数。原计划的强腿能力脉冲没有执行：根代理发现后脚尚未覆盖tail后，优先级改为接触可达性与踝目标的小反事实，避免把几何缺陷混进更大控制搜索。

- 轨迹SHA-256：`68bbcdc4f9735499ce2f81999c8e4eb89a54f6c5999ed45b233ccc8745df3d22`。
- 来源检查点SHA-256：`6cbedaaded3c626af214fc5136c99d0cca107e992160b414f84040612fbe66bf`。
- 参考仍为 `data/ollie/air_relative_video_timed_v1/joint_reference_50hz.npz`，SHA-256 `941f748cf3b13edbcf60dd20f2db41810cee2cbd1e9b4dccba1e3b1d4b5a71f5`。
- MuJoCo **3.16.0**；control_dt=0.02 s，8个0.0025 s子步。机器人质量 **33.341142 kg**，被动板含轮质量 **2.18 kg**。

从唯一初态连续执行保存动作到3.30 s，逐20 ms边界qpos/qvel误差为 **0**。通过 `mj_subtreeVel` 取得pelvis子树的机器人COM速度与板子树COM速度，再按质量合成联合COM；机器人根速度单独报告，不冒充COM速度。参考COM只用参考qpos/qvel做刚体运动学核算，不使用其forward产生的假设接触力当作实测力。

原生实际地面合力按每个真实接触frame和6维contact force转回world后求和。2.60～2.76 s扣除重力后的地面竖直冲量 **22.387 N·s**，联合COM动量变化 **22.419 N·s**，二者相差0.032 N·s；核算能解释真实系统动量，未凭根位置上升推断起跳。

文档36/39的局部WM梯度仍是另一次原始native0历史的审计。当前两种初始化轨迹很接近，但因双头混合的浮点运算，完整trace并非逐值相同；本文不把它们写成同一个精确快照。

## H8工程原型与论文目标的差异

`src/supermimic/ollie/learning.py` 的当前工程跟踪项为：机器人70维归一化误差平方均值×0.5，加板root12维误差平方均值×confidence×board_weight。机器人误差包含根位姿/速度以及29关节位置/速度；它不是COM动量、踩尾力或落板奖励。未知参考轮角/轮速不进入跟踪目标。

`scripts/local/train_ollie.py` 每步另加：根位姿前6维归一化误差平方均值×0.25、`10*relu(0.8-upright)^2`、动作相对参考关节的偏差×0.1、动作变化×0.02。折扣0.97，H8总和再除以8；可另加教师动作MSE×100。当前没有末端value/critic，也没有显式脚面向上承重、tail撞地、全板连续离地和稳定接板项；这些仍由原生评测验收。

文档40的robot-only配置关闭板跟踪梯度并detach跨步板状态，但仍采用上述机器人跟踪目标。名称“机器人起跳课程”并没有自动把目标变成整机COM起跳动量。准备网络保护到frame130=2.60 s，之后10帧混合，2.80 s完全切换；actor起始帧130～155，H8可看目标131～163。

H8只覆盖 **0.16 s**。从2.60 s看至2.76 s，尚未到参考pop标签2.88 s，也看不到真实后脚卸载、3.2575 s身体触地及更晚落地。即使从3.10 s开始，能看到的也只是局部结果，没有末端value来评价更后的恢复。策略的0/5/10未来目标提供运动意图，但不能代替动力学展开的回报视野。

[PAPER_SPEC.md](PAPER_SPEC.md) §9、§15已记录论文使用H32+critic终值、软存活权重；其消融为无critic时H≤16失败，有critic H16达到无critic H32水平。这是原论文LAFAN1实验结论，**不是Ollie必需H32的数学定理**。当前人板原型没有等价实现该目标结构，不能称为论文设定下的负结果。另一方面，文档36/39已发现板动作响应错误，直接扩大H32会放大不可靠的预测，新增critic也不会自动修复接触动力学。

真实回放代入当前state-dependent损失，可看到目标并非简单被关节维度数量支配。以下为相应时间区间控制帧均值，不是actor实际想象批的梯度归因，也未混入教师/动作正则项：

- 2.60～2.76 s：额外root pose项 **1.908**，关节位置部分0.217，根线速度部分0.0188。
- 2.76～2.88 s：额外root pose项 **4.080**，关节位置0.556，根线速度0.0550。
- 2.88～3.12 s：额外root pose项 **12.305**，关节位置1.458，根线速度0.241。

同区间upright barrier均为0：身体朝上不等于COM仍受脚板支撑。当前较大的位置/姿态跟踪项正追逐含明显动力学不一致的世界轨迹，不能据这些loss下降认定真实冲量或接触顺序变好。

另一个较小的语义边界：actor初始`previous`来自同一replay步已执行的action，首步rate项实际上把新动作锚到该真实action，并非严格使用t−1动作的平滑项；后续想象步才是相邻新动作差。这不是本轮已证明的主因。

## 真实动量与时序缺口

参考time_scale为 **1.5**：物理时间×1.5对应视频时间，50 Hz。参考阶段从2.10 s crouch、2.88 s pop、3.12 s flight、3.44 s landing开始；标签本身不认证真实接触。

关键时刻的机器人COM竖直速度：

- **2.40 s**：实际−0.6265 m/s，参考−0.3497 m/s，实际仍更快向下。
- **2.60 s**：实际−0.0963，参考+0.0983，实际尚未开始明显上升。
- **2.76 s**：实际+0.5762，参考+1.2321；差约 **21.87 N·s**机器人竖直动量。这是同一时刻的差，不表示可以独立注入这股冲量或只补一个速度就完成任务。
- **2.88 s**：实际+0.7597，参考+1.2047；联合COM实际水平速度已0.538 m/s，不能忽略横向跑偏。
- **3.00 s**：实际仅+0.0461，参考仍+0.7580；左右脚向上甲板支撑均为0。
- **3.12 s**：实际−1.1288，参考又要求+2.5202，已进入完全不同的动力学分支。

2.60～2.88 s内参考COM速度峰 **1.5460 m/s@2.78 s**，实际峰 **0.8488 m/s@2.8475 s**，晚67.5 ms且幅度低。实际峰速度对应的理想自由飞行上升量仅约 **36.7 mm**；此数只按v²/(2g)说明动量尺度，不是实测离地高度，也没有扣除之后支撑、转动和实际离板时刻差异。

实际根VZ在2.76 s为0.7802 m/s，而COM只有0.5762。根运动受腿与躯干内部姿态改变影响，直接优化root VZ方向不等同于给整个机器人足够起跳动量。原生评测始终没有合格踩尾/全板起跳，不能用一个向上的根速度取代验收。

## 参考空中动力学不一致

将同一参考的机器人和板按真实质量做联合COM核算，以下三个采样姿态**没有任何地面接触几何对**，整板完整盒/圆柱包络最低高度分别为：

- 3.14 s：**+98.42 mm**；联合COM VZ **2.60644 m/s**。
- 3.16 s：**+227.18 mm**；联合COM VZ **1.77380 m/s**。
- 3.18 s：**+257.87 mm**；联合COM VZ **0.89829 m/s**。

3.14→3.18 s，联合COM VZ减少 **1.70814 m/s**，而重力在0.04 s只应使其减少0.3924 m/s。若将这个采样段按无外力飞行解释，等效还需约 **−1168 N额外竖直外力**。同期联合COM水平速度从 **[−0.8567,−1.4299]** 变为 **[+0.3394,+0.3811] m/s**，也不符合空中水平动量近似守恒。

这是对参考采样轨迹动力学一致性的反例，不是视频人物真实受力测量，也不是对采样间任意插值路径的完整连续碰撞证明。三个姿态离地余量很大、COM速度与相邻COM位置差分也近似一致，不能把该变化简单解释为关节内部收腿：内部运动会改变根和各部件运动，但不能凭空改变整个“机器人+被动板”系统的质心动量。

参考此前经过人板几何修复，不代表已经满足运动方程。tail可达性修复仍需同时避免制造新的空中位置/速度拼接突变。当前不宜将高置信度root pose损失继续当成这一空中轨迹的可执行目标。

## 力矩、目标范围与BC偏置

2.40～3.30 s全部物理子步中，**腿部实际力矩达到原上限95%的样本占比为0**。2.60～2.76 s全身最大力矩占上限57.3%；左hip pitch峰50.39/88 N·m、后脚ankle pitch峰18.62/50 N·m。2.76～2.88 s峰值也只是左hip pitch53.30/88 N·m。出现5 N·m饱和的是手腕，不能误报为腿驱动已耗尽。

与此同时，左右knee的0.5 rad残差范围**没有被当前actor用满**。2.40～3.30 s原始残差最小分别−0.466 / −0.364 rad，达到95%残差边界的比例均0。不能把“目前未获得所需动量”直接归因于knee残差上限。

动作范围确实限制更强蹬伸的可表达性，但目前只是理论上限诊断：2.60 s左右实际knee约1.629 / 1.819 rad，最小policy目标`ref_next−0.5`仍为1.004 / 1.152 rad。用原Kp/Kd计算的最大伸膝请求约 **−57.9 / −62.7 N·m**；若只按真实关节范围选近伸直0.05 rad，则请求约−152 / −172 N·m，会由原139 N·m上限裁剪。**这不证明扩大范围就能跳，更不证明现策略已经碰到该边界**，本轮没有执行这种强控制或放宽任何限制。

BC结束后的后踝偏置需要区分三件事：相对参考残差、相对实际关节的PD误差、实际输出扭矩。不能仅因actor目标比参考更正就判成反馈反号。例如2.76 s右踝pitch实际−0.664 rad、速度+3.442 rad/s，下一动作+0.138 rad，对应原PD约 **+16.61 N·m**；2.88 s目标+0.445、实际−0.084、速度+6.400，对应只有 **+3.48 N·m**，速度阻尼已抵消大部分弹簧项。

只读准静力对照也说明有合理补偿成分：参考2.76 s在默认平板接触假设下可求平衡，右踝pitch所需约+16.14 N·m；加入参考速度补偿的目标约−0.062 rad。该假设的足点投影约7.06 mm，不能冒充精确接触真值。实际2.76 s姿态的静力解却失败，残差3.42 N·m、投影11.96 mm；2.88 s更失败，残差42.90 N·m、投影55.54 mm。失败解未被用于认证实际补偿或生成控制。

更明显的可疑行为是右踝roll目标在2.76 s后持续命中 **−0.2568 rad真实目标边界**。但它是否实际有害，仍需反事实，不能仅凭参考与目标符号不同作结论。

## 后踝roll四个固定真实反事实

新增 `scripts/local/probe_ollie_rear_ankle_roll.py`，只做四个固定分支，没有搜索或模型训练。实际结果在 `logs/ollie_rear_roll_probe_01/`：

1. 原actor基线。
2. 从warm 2.76 s开始的8个控制步，仅右踝roll目标改为对应`qref_next`。
3. 同8步仅该目标改为0。
4. 同8步从原目标逐步fade到`qref_next`。

其余28个动作逐值不变，8步后全部接回原保存动作至3.30 s。完整mjData副本保留warmstart、ctrl、efc_force及历史，无根/板写回、无额外力、无回合内重置。连续前缀与未扰动后继误差均 **0**。目标保持真实关节范围，原Kp/Kd、力矩上限和被动板不变。

按“基线 / qref / 0 / fade”顺序，H8终点2.92 s结果：

- 机器人COM VZ：**0.5996 / 0.5983 / 0.6045 / 0.5942 m/s**。
- 期间COM VZ峰：**0.8488 / 0.8248 / 0.8219 / 0.8264 m/s**。
- 右脚向上甲板支撑>1 N比例：**82.8 / 84.4 / 87.5 / 81.3%**。
- 后脚toe相对板面的角度：**−20.57 / −19.84 / −18.82 / −20.49°**。
- 全部 **tail真实力样本0、完整板包络没有离地**。

四个H8分支均无机器人触地，最大穿透3.47～3.53 mm、实际软关节角越界0.0254～0.0328 rad，均满足本次10 mm/0.05 rad诊断门槛；这不是原始参考初始化门槛或Ollie成功认证。

继续原保存动作后，首次身体触地分别 **3.2575 / 3.2600 / 3.2625 / 3.2575 s**，全部后续质量判定失败，仍无tail接触。单改roll稍改变后脚倾斜与支撑，没有恢复COM动量或起跳；**不支持把roll反号认定为主要失败原因**。后续为开环接原动作，并非重新闭环计算actor，不能据此评价完整恢复策略。

每分支保存28个92维控制边界状态、27个实际29维动作、qpos/qvel和50 Hz时间；逐子步contact/COM/足姿/软限位/穿透记录单独保存。没有标成teacher或成功示范。

## 后续边界与复核

几何审查已发现后足尚未覆盖tail，独立参考修复正在处理；本轮反事实也从未出现tail真实力。下一轮应先校验新的tail可达参考和无地接触段的联合COM动力学一致性，再做短原生回放。文档42的配对动作模型拟合用于补动力学辨识，不应只因训练loss下降就替代独立动作响应留出。

当目标与接触模型通过有限核验后，才有依据比较短窗动量课程、带终值/critic的较长视野等实现；不将“论文H32有效”当作跳过当前错误目标和错误板梯度的理由。当前所有结果仍FAILED，未认证完整Ollie。
