# Ollie 世界模型动作梯度审计

## 实际结论

本轮对冻结的在线第10轮世界模型做CPU原生MuJoCo动作干预。**滑板的动作梯度在这些接触状态下不可靠；机器人根竖直速度的梯度仍有实际可用方向，不能把整个模型的动作梯度一概判错。** 当前没有证据证明BPTT已经找到真实起跳控制，也不能仅凭本次单步检查断言它的全部优化收益来自模型漏洞。

最直接的反例：在真实连续回放的2.60 s状态，沿模型认为能增大板竖直速度的方向改变关节目标，模型预测增加 **0.001520 / 0.003771 m/s**，实际只增加 **0.0000019 / 0.0000205 m/s**，分别对应动作29维L2改变量0.02 / 0.05 rad。板实际几乎不响应，模型预测约大800 / 184倍。2.88 s同一类测试中，模型预测板向上增加 **0.001203 / 0.003004 m/s**，实际反而减少 **0.0000697 / 0.000978 m/s**。

同样沿模型的**机器人根竖直速度**上升方向执行，2.60 s预测增加 **0.006184 / 0.015459 m/s**，实际增加 **0.007690 / 0.019280 m/s**；本轮所有6个状态/动作基点、每点两个幅度的这类方向测试均实际向上。因此主要问题表现为学到的板接触响应与接触切换，而不是已发现自动微分断链或整个动作接口失效。这里的根速度不等于整机COM速度。

## 原生历史与动作契约

从native_0000保存的唯一初始状态开始，逐个执行原记录的29个机器人位置目标；每20 ms连续执行8个0.0025 s子步，并按原评测流程在子步后调用forward。只在最初写入qpos/qvel，前缀中没有重新置根、修正轨迹或注入外力。

每个控制边界与原存档比较，直到2.88 s的**qpos和qvel最大绝对误差均为0**。到2.60、2.76、2.88 s后复制完整mjData，再由各自独立副本步进；保存和检查qpos、qvel、ctrl、qacc_warmstart、efc_force、外力数组等历史，副本不共享qpos/warmstart内存。相同动作的重复分支逐值相同；未扰动的初始actor动作分支与原存档下一帧也精确相同。没有仅取qpos/qvel冷启动接触求解器。

三个时刻的真实支撑情况：

- 2.60 s：4轮接地，左右脚向上甲板支撑约222.55 / 196.90 N；最大穿透0.428 mm，实际软关节角越界0.01619 rad。
- 2.76 s：4轮接地，左右脚支撑273.63 / 181.51 N；最大穿透2.859 mm，实际软角越界0.00983 rad。它是原始连续回放中的真实状态，未通过重新置姿把穿透降到初始化门槛。
- 2.88 s：3轮接地，左右脚支撑255.79 / 24.04 N；最大穿透0.464 mm，实际软角越界0.01814 rad。

三个快照均无机器人触地，外部广义力/body force均为0。这些软约束越界如实保留，不把目标角合法等同于实际角从不越界。

每个状态测试两个动作基点：原生存档的初始actor下一动作，以及**第10轮actor在同一真实状态**计算出的动作。后者未来目标严格按原评测 `min(step+1+offset,last)`，offset为0/5/10。它只改变当前动作基点，没有把实际状态换成模型想象状态。

执行控制按 `index.robot_actuators` 映射，而非假定actuator原始数组顺序与G1关节顺序相同；按原真实目标范围保留0.005 rad边距裁剪。原质量、重力、接触、驱动增益和力矩上限未改动，板仍无驱动。

## 计算与非光滑边界

对每个基点29个关节分别施加±0.005 / ±0.02 rad，保持其余目标不变，实际步进20 ms，取得条件有限差分割线。检查8个输出：机器人根world XYZ和world VZ、板根world XYZ和world VZ。92维状态中对应索引为 `[0,1,2,38,71,72,73,84]`，不是板COM或轮心代理。

世界模型在同一真实state/action上以float32自动微分，原生仿真为float64。比较时排除中央扰动被真实目标限位裁成不对称的关节：2.60 s为29个，2.76 s为27个（排除左右ankle_roll），2.88 s为28个（排除right_ankle_roll）。原始实际±动作幅度、裁剪名单和所有关节行仍保存，未隐藏边界关节。

额外沿各模型自己预测的robot Z/VZ与board Z/VZ上升方向执行L2半径0.02 / 0.05 rad，裁剪后的真实动作与模型重新预测都保存。这直接检验模型的可执行方向，而不仅比较一个高维cosine。共完成696个逐关节干预分支、96个模型方向干预分支及12个未扰动/重复分支。

有限差分不是接触光滑导数证明。每个分支保存逐子步有效接触对是否改变；仅force>0.1 N的真实接触计入signature。2.76 s原始动作附近，epsilon从0.005改为0.02时，root-VZ割线范数 **2.564→0.860**，板-VZ **0.0493→0.0158**，接触对变化关节数 **14→23**。此处不能选一个epsilon就称为唯一真实梯度。

较稳定的对照：2.60 s原始动作的root-VZ两个epsilon割线cosine为 **0.99962**；2.76 s第10轮actor动作基点为 **0.99855**。这表明输入动作基点改变后，同一快照的接触分支稳定性也会变化。2.88 s原始动作的板-VZ两个epsilon割线cosine仅 **0.21955**，须保留显著的接触非光滑不确定性。

## 方向与幅度结果

以下比较均使用第10轮WM，梯度范数单位为 `(m/s)/rad`。同一状态的初始actor动作基点与第10轮actor动作基点不能混为同一局部线性化。

- **2.60 s原始动作**：root-VZ模型/原生范数比0.617 / 0.615，cosine0.773 / 0.765；板-VZ范数比 **46.4 / 56.1**，cosine0.314 / 0.423，依次对应epsilon0.005 / 0.02。真实板割线范数只有0.00165 / 0.00136，绝对响应很小，不能只报倍数而忽略分母。
- **2.76 s原始动作**：root-VZ cosine −0.098 / 0.168，板-VZ −0.317 / −0.315；这里同时存在上节所述显著epsilon敏感性，不能把反向cosine单独当作确定导数结论。换到第10轮actor动作基点后root-VZ cosine0.722 / 0.725，而板-VZ范数仍被放大 **9.79 / 15.23倍**。
- **2.88 s原始动作**：板-VZ范数比0.0437 / 0.1253，cosine−0.135 / 0.166；模型没有正确描述接触切换时的板响应。第10轮actor动作基点的板-VZ cosine0.334 / 0.309，也未达到可信的方向一致性。

模型自身自动微分与其自身有限差分一致：两个VZ通道各epsilon汇总相对L2误差均小于 **0.00029**。因此此轮没有发现“自动微分计算错了”这一解释；当前反例指向学习得到的转移动力学与真实接触响应不一致。

直接上升方向的实测还保留一个限制：2.88 s换到**第10轮actor动作基点**后，沿其板-VZ模型梯度实际确实向上（0.02 / 0.05 rad分别+0.002330 / +0.005822 m/s）。因此“板梯度处处反向”也是错误结论。原始动作基点的反向案例证明局部不可依赖，不能推广成整个动作区域的统一符号规律。

第10轮actor相对初始actor的整29维动作变化，在相同2.60 s快照上让模型预测板VZ增加0.000858 m/s，实际变化−0.000012 m/s；在2.88 s模型预测减少0.002433 m/s，实际增加0.018326 m/s。actor更新的这些实际变化也展示了板响应预测误差，但并不等同于actor loss的完整H8梯度归因。

## 对后续训练的含义

本次为**单步状态/动作局部审计**，不是完整H8 BPTT的反向传播归因。它确认：低单步位置误差不能保证动作梯度可信；特别是模型可凭错误板响应给优化器提供虚假的向上方向。不能只继续增大BPTT预算并用想象轨迹当作实际起跳证据。

下一步应使用同一warm接触历史的真实动作分支数据，补充模型在动作干预下的辨识与整回合留出；单独报告支撑、接触切换、自由飞行/碰撞，不把合成空中初始化当作真实起跳示范。仍需保留原生MuJoCo连续评测与整板几何+真实力+连续窗口验收。更大的单关节干预和H8实际分支由独立文档38记录，本轮没有修改训练入口、参考或物理参数，也没有恢复PD搜索。
