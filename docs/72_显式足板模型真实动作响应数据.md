# 显式足板模型真实动作响应数据

本批完成 **217 个原生 MuJoCo 热状态分支、1736 条真实转移**，用于 SuperMimic 人板世界模型的动作响应与接触辅助监督。没有训练策略或世界模型，没有改用 PPO，没有生成教师，也没有成功 Ollie 的声明。

全部分支有限且完成 H8；同动作重复的状态、速度和接触标签误差均为 0。数据只覆盖现有轨迹的支撑与卸载响应：**尾部触地、前脚对鼻端净上提、整板离地超过 5 mm 均为 0 个分支**。它不能证明起跳/带板阶段的模型响应可信。

## 固定来源与试验

入口为 `scripts/local/collect_ollie_mu09_responses.py`。先执行 `--mode inspect` 保存固定清单，随后 `--mode run` 要求清单、代码与来源绑定完全一致。本次原生采集与输出耗时 **9.20 s**，低于 120 s 预算；未更改锚点、扰动或阈值重试。

- 来源为 65 号完整实际轨迹 `logs/ollie_contact_sequence_01/actual_rollout.npz`，SHA256 `8b602ad7f88266ba831c71df6c0f25bc84366a3af13427166e559f45d4470cb7`。原 257 组目标的原始数组 SHA256 为 `69483aa82bd261560cc60ee29b7f3cf9a58ee1327938dc47bb3db5c52200094b`。
- 使用原 29 个 G1 关节 PD、电机上限和被动板，仅采用来源已显式定义的 42 个足板接触对、摩擦系数 0.9。这是未实测校准的工程模型分支，不能与原默认足板摩擦 0.6 的数据无条件视为同一动力学。
- 原板 XML 保持不变，SHA256 为 `b0275651d4ca6e8455e0a8cdcf65204078017007c8c3416635b2460050bfc17b`。相等约束、板电机、mocap 均为 0；没有施加 `qfrc_applied/xfrc_applied`。
- 从唯一原始初态连续执行全部 257 组来源目标至 5.14 s；258 个边界的 `qpos/qvel/state92` 最大误差均为 0，2057 条原 ContactObserver 记录的全部字段逐值相同。
- 在控制帧 **120、130、140、146、149、160、240**，即 2.40、2.60、2.80、2.92、2.98、3.20、4.80 s，复制完整实际 `MjData`。分支继承控制、接触、约束、求解器 warmstart 等历史，不以仅设置冷 `qpos/qvel` 代替热状态。
- 每个锚点为 1 条原动作基线，另对依原顺序排列的 12 个腿关节、3 个腰关节分别做 ±0.06 rad 扰动，共 31 条分支。只改变首个 20 ms 目标，随后 7 组目标恢复该来源时间对应的原值，H8 总长 0.16 s；按原真实关节范围留 0.005 rad 边距裁剪。

每条分支只初始化一次复制出的热状态，期间不重置或覆盖根/板状态。它们是共享锚点的短动作干预分支，不是 217 次独立完整技巧回合。7 条基线 H8 的全部状态还与原 65 号对应片段逐值相同；热状态复制源在全部分支运行后指纹保持不变。

## 数据接口

目录为 `logs/ollie_mu09_responses_01/`。`manifest.json` 是运行前固定清单；`dataset_manifest.json` 在其基础上追加输出文件校验和，避免把文件自身哈希循环写入文件元数据。

`paired_responses.npz` 的主要数组：

- `state[217,9,92]`、`qpos[217,9,47]`、`qvel[217,9,45]`，均为实际 float64 状态；`action[217,8,29]` 为真正执行的合法绝对 PD 目标。
- `post_forward_metrics[217,8,8,49]`：每个 50 Hz 控制含 8 条 400 Hz 观测，按公开 `METRIC_NAMES` 顺序保存。每次实际 `mj_step` 后执行 `mj_forward`，再由原 ContactObserver、原生接触力与质心 Jacobian 提取；未调用 GPU 或伪造 Warp 数据。
- `anchor_frame/group_id/branch_id` 标识分组，`joint_index/joint_name/sign` 标识干预。基线 joint index 为 −1、sign 为 0；其余为 +1/−1。每锚点顺序为基线、每关节正向、负向，因此基线 ID 为 0、31、62、93、124、155、186。
- `paired_baseline_id` 指向同锚点的实际原动作基线。`requested_delta[217,29]` 保存请求扰动，`actual_delta[217,8,29]` 保存执行目标相对原来源目标的差；裁剪后实际幅度不能用请求的 ±0.06 代替。本批有 **9 条分支**发生扰动裁剪。
- `valid_complete[217]`、`transition_valid[217,8]` 标记实际完成情况。本批全部为真。入口会保留异常分支并显式标出未执行的填充数据，不把填充当真实转移。
- `train_mask/heldout_mask` 为锚点整组固定划分，`metric_names` 为 49 列名称，`metadata_json` 包含来源、原目标、板 XML 哈希、模型分支、原生后端、关节顺序与时间契约。

`transitions.npz` 按分支优先、步次其次展开：`state/next_state[1736,92]`、`action[1736,29]`、`contact_metrics[1736,8,49]`，并保留 branch/group/anchor/joint/sign/step、配对基线 ID、实际扰动、有效性与划分。`quality.npz` 保存每分支实际穿透、软关节限位偏差及真实接触事件标记，不筛掉失败数据。

49 列与 GPU 观察契约一致，但本批完全为 **原生 MuJoCo float64**。左右 `board_fz` 是板对脚的净世界 Z 力，站立时通常为正；`front_nose_board_fz` 是左脚对鼻端的净世界 Z 力，上提板时为正。分类阈值为法向力 0.1 N，上表面承重另按总和 >1 N 解释。原生 `overflow` 列为 0，表示原生动态接触存储，不冒充 GPU 容量监测。

这些标签是 **post-forward 观测力**，不能把它们乘时间后直接当作先前积分阶段的精确冲量，也不能直接作为外力写回滑板。

## 固定划分与实测质量

锚点 **146 与 160** 的全部 62 条分支、496 条转移为留出组；其余 155 条分支、1240 条转移用于训练。正、负及基线不会跨同一锚点拆分。

邻近来源时间窗仍有重叠，例如训练锚点 140 的 H8 覆盖到 2.96 s，而留出锚点 146 从 2.92 s 开始。因此这是“锚点动作干预留出”，不是全新时间段或全新动作的泛化测试，不能夸大为完全未见的物理状态。

本批全部 217 条分支满足原有穿透 ≤10 mm、实际关节软偏差 ≤0.05 rad 的记录门槛；最大穿透 **5.802 mm**，最大实际软限位偏差 **0.03122 rad**。没有机器人几何触地。所有目标均核对在原关节目标范围内；所有分支首状态与其配对基线首状态逐值相同，后 7 组控制全部恢复来源原值，400 Hz 标签时间全部对齐。

每个锚点额外把基线、首个关节正向和负向控制各重复一次，仅作确定性核对，不计入主数据的 217 条分支/1736 条转移。21 条相同热状态、相同动作重放的 `state/qpos/qvel/49列metrics` 最大误差全部为 **0**。这是该原生配置中的观测噪声地板，不是所有后端和接触情形的普遍零误差保证。

## 配对板响应摘要

`paired_gain_sign.json` 保存每个锚点、关节、H1/H8 的板根高度、板根竖直速度与板质心竖直速度响应。正负响应均相对同热状态原动作基线；secant gain 用真实裁剪后的正负动作差作分母，不能默认为 0.12 rad，也不能无条件解释为接触动力学的解析导数。

板根竖直速度的正负分支差绝对值，按中位数 / 90 分位 / 最大值报告：

- 训练组 H1：**0.00003598 / 0.0006963 / 0.002714 m/s**；H8：**0.0001529 / 0.01529 / 0.04389 m/s**。
- 留出组 H1：**0.0004117 / 0.002361 / 0.007586 m/s**；H8：**0.00003708 / 0.005320 / 0.01479 m/s**。
- 训练组 75 对，H1 secant gain 为正/负各 45/30 对，H8 为 38/37 对；留出组 30 对，H1 为 10/20 对，H8 为 16/14 对。方向随状态和关节改变，不能预设“某个动作方向总会使板上升”。

训练与留出响应尺度明显不同，必须与零动作响应预测基线一起报告。所有分支都没有真实尾撞、鼻端上提或全板离地；辅助头若只学会预测“无事件”，不能据此解除板相关 BPTT 梯度限制。
