# ollie.mp4 的视频人体恢复接入记录

记录日期：2026-10-23，Asia/Shanghai。这里只记录真实运行的视频前端；G1 与滑板的物理仿真由后续交互任务负责。

## 已完成的结果

本机已经真实跑通 **原视频 → YOLO 人物追踪 → ViTPose → HMR2 特征 → GVHMR → SMPL-X 22 关节 FK → 原画面骨架叠加**。

- 输入：`video/ollie.mp4`，1920×1080，186 帧，24000/1001 FPS，容器时长 7.757750 秒。
- 原视频末帧 PTS：7.716042 秒。不能将容器结束时间当作最后一帧的时间戳。
- 工作输入：按真实 PTS 重采样到 30 Hz，共 233 帧，末帧时间 7.733333 秒。保留播放速度，没有推断或修正慢放倍率。
- 相机：近固定假设；少量镜头抖动暂未估计。
- 推理：使用真实 SMPL-X NEUTRAL 模型，没有使用 SMPL-H 替代或手写动作。
- 后处理：`none`，禁用普通地面静止脚/手的轨迹与 IK 修正。滑板上的脚可能随板运动，不能直接锁到地面。
- 第一次完整前端运行：**29.08 秒**，Torch 峰值已分配显存 **3.07 GiB**。不含环境安装、权重下载与视频归一化；不是整机显存峰值，也不是机器人训练耗时。
- 数值结果：233 帧参数和 22 关节位置均为有限值。已查看四帧骨架叠加，主体追踪及二维骨架位置与人物基本一致；这不证明三维动作或接触已经正确。

本机输出保留在被 Git 忽略的目录：

## 代码与独立环境

官方代码：[zju3dv/GVHMR](https://github.com/zju3dv/GVHMR)。本地固定在 `ee960bb6e2ea2d381aa97f08e9b71ef320b624b1`，位于 `references/GVHMR`。

独立环境是 `references/GVHMR/.venv`，没有修改 SuperMimic 根目录 `.venv`、CUDA 驱动或训练算法。实测核心依赖：

- Python 3.10.12。
- Torch 2.3.0+cu121、TorchVision 0.18.0+cu121。
- PyTorch3D 0.7.6，使用上游 requirements 指定的 Python 3.10 / CUDA 12.1 / Torch 2.3 官方预编译轮子。
- NumPy 1.23.5、SciPy 1.13.1、SMPL-X 0.1.28。
- Lightning 2.3.0；其依赖解析得到 PyTorch Lightning 2.6.6，已完成本次实际推理。
- Hydra 1.3.0、OmegaConf 2.4.0、timm 0.9.12、Ultralytics 8.2.42、OpenCV 4.11.0.86。

首次前端环境的完整依赖快照保留在 `references/GVHMR/requirements.local.freeze.txt`。后续 GMR 如复用此环境安装 CPU IK 依赖，应避免升级 Torch、NumPy 与 CUDA 组件；该快照保留前端完成时的状态。

脚本职责：

- `scripts/video/setup_gvhmr.sh`：克隆/检查固定版本，建立独立环境并安装上游依赖。
- `scripts/video/gvhmr_constraints.txt`：本次通过实际推理的核心依赖版本约束，只用于视频前端环境。
- `scripts/video/download_gvhmr_assets.py`：固定版本、SHA256 校验与可续传下载；不使用登录凭据。
- `scripts/video/recover_gvhmr.py`：时间轴归一化、调用上游前处理和网络、导出真实参数/FK，并生成骨架叠加。
- `scripts/video/audit_gvhmr_coordinates.py`：只读 CPU 坐标审计，不修正或替换动作。

## 重跑方式

从 `/home/zxc/SuperMimic` 执行。首次准备环境/权重可以使用：

```bash
bash scripts/video/setup_gvhmr.sh --include-body-model
```

`--include-body-model` 明确选择上文记录的公开第三方 SMPL-X 副本。也可自行按官方流程获得模型并放置到同一路径，随后只下载其他推理权重。

已有完整环境时，运行真实恢复：

```bash
env -u PYTHONPATH -u PYTHONHOME PYTHONNOUSERSITE=1 \
  OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
  references/GVHMR/.venv/bin/python scripts/video/recover_gvhmr.py \
  --video video/ollie.mp4 --camera static --postprocess none
```

前处理缓存已经存在时可加 `--stage recover`，只重新执行网络/FK/叠加；`--stage prepare` 只做 CPU 视频/PTS 归一化；`--stage preprocess` 只做人物/二维姿态/特征提取。更换原视频请使用新输出目录，避免错用缓存。输出目录通过 `--output-root` 指定。

CPU 坐标检查：

```bash
env -u PYTHONPATH -u PYTHONHOME .venv/bin/python \
  scripts/video/audit_gvhmr_coordinates.py \
  --motion logs/ollie_gvhmr/ollie/body_world_raw.npz \
  --body-model references/GVHMR/inputs/checkpoints/body_models/smplx/SMPLX_NEUTRAL.npz \
  --output logs/ollie_gvhmr/ollie/coordinate_audit.json
```

## 输出坐标和后续人板对齐

`hmr4d_raw.pt` 含 `smpl_params_global`、`smpl_params_incam`，各有 `body_pose (233,63)`、`global_orient (233,3)`、`transl (233,3)`、`betas (233,10)`；另含 `K_fullimg` 与模型预测的静止关节 logits。

`body_world_raw.npz` 另含以下可用字段：

- `joints_world/joints_camera (233,22,3)`：相同 22 个 SMPL-X 身体关节的世界/相机位置，单位米。
- `joint_rotmat_world/joint_rotmat_camera (233,22,3,3)`：对应关节的全局旋转矩阵，不是父关节局部旋转。
- `joint_names/parents`：关节名称与父索引。脚踝索引 7/8，脚部索引 10/11，均不是鞋底的真实接触点。
- `K_fullimg (233,3,3)`：本次 `fx=fy=2202.9072265625`、`cx=960`、`cy=540`；这是上游默认估计，非相机标定值。
- `keypoints2d_coco17 (233,17,3)`：ViTPose 的二维像素坐标与置信度；可用作遮挡检查，不能当三维真值。
- `predicted_static_joint_confidence (233,6)`：网络的静止关节概率预测；不是脚-板接触标签。
- `camera_to_world_rotation/translation`：由同帧人体 root 的世界/相机姿态反推，使 `p_world = R @ p_camera + t`。22 关节对应最大绝对误差约 `1.52e-6 m`。这只是预测间的数值一致性，**不是独立标定的相机外参**。
- `time_seconds/nearest_source_frame`：30 Hz 工作时间轴和原视频帧映射。

特别注意：

1. GVHMR 世界坐标是 **Y 轴朝上**，不能直接当作 MuJoCo 的 Z-up。后续必须对人体、板、地面统一转换坐标基。
2. raw 世界的地面未做平移标定。双脚 Y 约在 `-1.2 m`，这不意味着已经穿过真实地面；也不能逐帧将脚强制平移至零。
3. 相机近固定时，推导出的 `camera_to_world` 仍有明显时变：相对首帧旋转最大约 `9.74°`、中位 `4.73°`；平移逐轴范围约 `0.56/0.60/1.16 m`。不能把这些人体预测误差直接当作真实相机运动来移动滑板。
4. 应先在共同 camera frame 中拟合人体和板，再以单一固定世界变换/共同优化完成重力、地面和尺度对齐；原始结果单独保留。
5. 预测 shape 的静态表面高度约 `1.732 m`，属于模型尺度估计，非已知真人身高。两脚接触板的位置、地面高度、板的 6D 位姿仍需额外估计。
6. 世界 pelvis 的 X/Y/Z 范围约 `0.170/0.361/0.210 m`。关键时刻的骨盆、脚踝和脚部三维位置已保留在 `coordinate_audit.json`，必须结合板观测和遮挡置信度解释。

本前端提供真实估计和可追溯时间轴，不将人体骨架叠加当作 G1＋滑板物理成功视频。
