# Ollie可回收抬脚姿态先验

2026-10-25。**A/B两个80 mm节点及随后预先固定的C高收腿节点，均通过原关节限位和几何检查。**C的软朝向误差较大且两个踝目标到达内缩边界，不能把位置可达改写成完整脚姿严格不变。这些结果只提供腿部姿态先验，没有执行PD控制、积分、搜索动作或训练，也不是教师。

动机是76真实回合已产生65 ms整板腾空，但前脚在此前已向板侧移出，后脚随后越过尾端，未完成接板。[77号释放机制记录](77_Ollie释放机制与接触目标修正.md)及76的独立审计区分了真实板腾空与完整回合失败。本次不改变原12°板、默认足板μ=.6、尾地材料、质量、电机或验收规则。

## 固定来源与目标

唯一来源为`logs/ollie_pop_events_preflight_02/actual_rollout.npz`，SHA256：

`43cfef43b9cf5f966df2bb0a8b7e31a2446ee040f6fef5d3cab10baf221c027d`

取第150个控制边界，即3.00 s的真实qpos。旧轨迹在这个时刻的左脚site板局部坐标约`[.166367,.061303,.046934] m`，到有限deck盒的最短间隙约.370 mm；3.04 s时site Y已到.101624 m，接近板半宽.105 m，3.08 s到.152235 m。本次在侧移明显扩大前求可回收姿态，不延续“只要足力为零”的目标。

优化变量仅为G1命名顺序的12个腿关节。机器人自由根、板、四轮、腰和手臂的qpos均逐值固定于源帧。左/右脚初始站姿XY从同一不可变来源的frame0经原模型FK取得：

```text

right XY = [−.3199999954772410, +.022452886643490760] m
```

板局部+X为nose，+Y沿轮轴，+Z向上。所有目标均是实际`left_foot`/`right_foot` site，**site不等于足胶囊最低点**。初始右脚在tail斜面上，不能把两脚site Z统一设为中心面高度.006 m。

- 节点A `front_lift_recover_xy`：左脚XY回上述初始值，世界Z等于源帧左site Z加.080 m；右脚的完整源site位置、朝向作为软保持目标。
- 节点B `both_lift_recover_xy`：双脚XY各回初始值，世界Z分别等于各自源site Z加.080 m。
- 两节点的脚朝向均软保持源frame150朝向；没有另换鞋姿或搜索翘角。

固定板旋转`R_B`和板原点`p_B`时，抬脚目标世界位置`p*`通过下面三个线性方程重建，而不是把板局部Z与世界Z混用：

```text
(R_Bᵀ (p* − p_B))[0:2] = 初始站姿板局部XY
p*[2]                  = 源site世界Z + .080
```

## 单次有界IK的方法

每个节点独立从同一源实际q12开始，只调用一次`scipy.optimize.least_squares`，无随机初始化、参数网格或失败重试；`max_nfev=120`。实际函数评估分别12、14次，总wall约2.02 s。

残差为双脚位置误差/.005 m、相对源朝向的旋转向量、`.02×(q12−q12_source_actual)`，以及原生启用接触对超过.5 mm的穿透/.001 m。碰撞项按固定geom pair槽位聚合，避免接触个数变化改变残差维度。只有原生过滤后实际启用的碰撞参与该项，没有把原本禁用的相邻连杆对偷偷启用。

目标边界为每个原真实关节范围内缩5 mrad。最终门槛另行检查：两个site误差均≤2 mm，全部启用接触穿透≤2 mm，抬起的脚到有限center/tail/nose盒间隙≥5 mm，双脚到ground间隙均≥5 mm，其他qpos逐值未变。软朝向残差如实报告，没有把朝向误差删掉或只看site位置。

临时可复跑诊断代码位于`logs/ollie_recoverable_foot_prior_01/solve_static_priors.py`。代码使用`mj_forward`和`mj_geomDistance`，积分步数为0；静态数据的qvel和ctrl置零只为几何检查，不代表复用真实solver热态或动态平衡。

## 实际角、动态目标与姿态先验必须区分

源3.00 s的实际腿角与正在执行的电机目标并不相同：

```text
source actual q12:
[−.8784750101, +.2266520700, −.0378625234, +1.0102397811,
 +.0673732115, −.2511529907, −.2764599185, −.1316263631,
 +.1872942708, +.6001214236, −.4527114804, +.1399644800]

source executed ctrl12:
[−.6481534831, +.2369320231, −.2027551513, +1.2108258411,
 +.5186000000, −.2137458273, −.7705649616, −.1274421940,
 +.1193292014, +.5606556400, −.0085977936, +.0283426211]
```

例如右hip pitch的实际角为−.276460，而源ctrl为−.770565；右ankle pitch实际为−.452711，ctrl为−.008598。若把节点A的右实际角直接覆盖到ctrl，反而会改变原drive。不能因为静态IK右腿未变，就宣称这样施加目标仍保留驱动。

姿态增量`Δq = qIK − source_actual_q`可以解释节点相对实际姿态的改变；若采用保留源PD误差的残差初始化，其公式为：

```text
candidate_ctrl(t) = clip(source_nominal_ctrl(t) + phase(t) × Δq,
                         original_joint_range 内缩5mrad)
```

节点A右腿Δq严格为0；节点B右腿Δq约`[−.277540,+.061799,+.025405,+.615191,−.332291,−.005915] rad`。这种映射**不是重力补偿或动态可行性证明**。原左ankle pitch目标已到+.5186，正增量会被截断，还会保留不希望继续执行的饱和踝驱动。因此root后续候选明确改为**active左腿采用绝对IK6目标，右腿在释放前保持原动态ctrl不变**，没有把上式自动作为最终控制配置。实际执行仍必须保存截断后的29目标，也不能使用`qIK−source_ctrl`混淆两种量。

非腿的`q29_static`条目同样只是源实际角，不是原电机ctrl。实际控制不复制本文件保存的自由根、板或轮qpos；它们只用于审查几何。
